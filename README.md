# 육삼빌딩의 세계

브라우저에서 실행하는 학생용 RPG 웹앱 게임입니다. 현재 목표는 기존 ChatGPT 수정 과정에서 커진 코드를 안전하게 정리하고, 이후 30명 정도의 학생이 함께 사용할 수 있는 구조로 발전시키는 것입니다.

## 현재 상태

2026-07-04 기준으로 1차 리팩터링과 안정화 검사는 완료되었습니다.

- `game.js`는 아직 가장 큰 메인 파일입니다.
- 데이터 일부는 `src/` 아래 모듈로 분리되었습니다.
- 중복 함수와 의심 로직 일부는 정리되었습니다.
- v35 스킬창 스타일은 `game.js`에서 빠져 `style.css`로 이동했습니다.
- 펫/강화 흐름에서 최신 함수로 대체된 일부 예전 alias를 제거했습니다.
- 기본 검사와 데이터 검사는 모두 통과하는 상태입니다.
- 아직 실제 브라우저 플레이 자동 테스트는 없습니다.

즉, 새 기획을 시작할 수 있는 상태이지만 완성/출시 상태는 아닙니다.

## 파일 구조

- `index.html`: 화면 뼈대, 버튼, 모달, 캔버스가 있는 파일입니다.
- `style.css`: 전체 UI 디자인과 배치가 들어 있는 파일입니다.
- `game.js`: 실제 게임 진행, 전투, 이동, 상점, 퀘스트, 저장 로직이 많이 남아 있는 메인 파일입니다.
- `src/core-utils.js`: 여러 곳에서 같이 쓰는 작은 공용 함수 모음입니다.
- `src/game-data.js`: 직업, 경험치, 기본 아이템, 기본 몬스터, 기본 세계 데이터입니다.
- `src/quest-data.js`: 퀘스트 데이터입니다.
- `src/patch-data.js`: 펫, 강화, 던전, 후반 패치성 데이터입니다.
- `tests/`: 코드 분리와 데이터 상태를 확인하는 테스트입니다.
- `tools/run-baseline.ps1`: 테스트와 데이터 추출을 실행하는 도구입니다.
- `schema.sql`: 나중에 온라인 서버/DB로 갈 때 참고할 수 있는 초기 SQL 초안입니다.
- `assets/`: 배경음, 효과음, 이미지 파일입니다.
- `data/game-data.snapshot.json`: 현재 게임 데이터가 깨졌는지 비교하기 위한 스냅샷입니다.
- `시트/`: 기획용 엑셀 자료가 들어 있는 폴더입니다.

## 지금 가장 조심해야 할 점

`game.js`에는 v17부터 v35까지의 패치 흐름이 아직 남아 있습니다. 이 패치들은 기존 함수를 덮어쓰거나 이어 붙이는 방식이 많습니다.

그래서 앞으로는 아래 방식으로 작업하는 것이 안전합니다.

1. 새 기능을 바로 `game.js` 맨 아래에 패치처럼 붙이지 않습니다.
2. 먼저 데이터인지, 계산 함수인지, 화면 동작인지 구분합니다.
3. 데이터는 가능하면 `src/game-data.js`, `src/quest-data.js`, `src/patch-data.js` 쪽으로 뺍니다.
4. 순수 계산 함수는 `src/core-utils.js`나 새 모듈로 분리합니다.
5. 화면과 직접 연결된 코드는 마지막에 조심해서 다룹니다.
6. 수정 후에는 반드시 전체 테스트를 돌립니다.

## 테스트 실행

이 프로젝트는 로컬 Node가 없어도 Codex 번들 Node를 찾아 실행하도록 `tools/run-baseline.ps1`이 준비되어 있습니다.

전체 검사:

```powershell
powershell -NoProfile -ExecutionPolicy Bypass -File tools/run-baseline.ps1 all
```

package 스크립트로 실행:

```powershell
node --run test
```

개별 검사:

```powershell
node --run check:syntax
node --run test:baseline
node --run test:core-utils
node --run test:game-data
node --run test:quest-data
node --run test:patch-data
node --run test:refactor-health
node --run test:current-data
```

## 다음 개발 순서 추천

1. 문서 정리
2. 직접 플레이하면서 버그 목록 작성
3. 브라우저 자동 테스트 추가
4. 30명 동시 접속용 서버 구조 기획
5. 새 기능 개발

30명 동시 접속은 현재 로컬 파일 구조만으로는 어렵습니다. 지금 저장 방식은 브라우저 `localStorage` 중심이라, 실제 동시 접속을 하려면 서버, DB, 로그인, 저장 동기화 구조가 필요합니다.

## 비개발자용 요청 문장 예시

Codex나 ChatGPT에게 수정 요청을 할 때는 이렇게 말하면 안전합니다.

```text
기존 동작은 유지하면서 수정해줘.
먼저 관련 파일과 테스트를 확인하고,
수정 후에는 전체 테스트를 돌려서 깨진 곳이 없는지 확인해줘.
game.js 맨 아래에 새 패치처럼 무작정 덧붙이지 말고,
데이터/계산/화면 동작을 구분해서 안전하게 고쳐줘.
```

버그를 설명할 때는 아래 형식이 좋습니다.

```text
어떤 화면에서:
무엇을 눌렀는지:
기대한 결과:
실제로 나온 결과:
콘솔 오류가 있으면:
```
