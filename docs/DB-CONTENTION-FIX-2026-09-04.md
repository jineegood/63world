### 던전 DB 잠금

`202609040001_raid_lock_order_v1.sql`은 heartbeat만 변경한다.

- 기존: 멤버 수정 잠금 → 방 잠금. 다른 던전 작업은 방 → 멤버여서 교착 가능.
- 수정: 잠금 없는 멤버 권한 사전 확인 → 방 잠금 → 멤버 수정/활성 여부 재확인.
- 비회원 `NOT_MEMBER` 우선 오류, 문제 준비 장벽, 제한 시간, 전투 판정, 보상, 30분 무활동 만료 정책 유지.
- 함수 실행 권한은 기존처럼 `service_role`만 허용한다.

### 채널 DB 잠금과 중복 작업

`202609040002_world_presence_lock_v1.sql`은 v1/v2/v3 호환 함수를 교체하고 비공개 내부 함수를 추가한다.

- 기존 v3 → v2 → v1 호출에서 접속 상태를 두 번 저장하고, 버릴 전체 마을 조회도 수행했다.
- v1의 채널 없는 INSERT 때문에 실제로는 2~10채널에 있어도 기본 1채널 잠금을 기다렸다. 1채널이 꽉 찬 경우 다른 채널도 잘못 거부될 수 있었다.
- 수정 후 실제 채널을 명시해 한 번 저장하고, 필요한 해당 채널 목록만 조회한다.
- 동일 사용자의 요청은 사용자 → 대상 채널 순으로 잠근다. 구버전 heartbeat와 채널 이동이 겹쳐도 이전 채널로 덮어쓰지 않는다.
- 기존 10개 채널, 자동 입장 시 채널당 3명 우선 분산, 수동 입장 정원 8명, 정원 트리거, 채널별 채팅/이동 권한, 전체 알림을 유지한다.
- v1/v2의 구버전 전체 목록 응답을 유지한다. 비공개 함수는 학생/익명 사용자가 직접 호출할 수 없다.

### 던전 클라이언트 요청

`src/raid-run-ui.js`, `src/raid-party-client.js`:

- 주기 heartbeat와 재조회(sync)는 한 요청이 끝나야 다음 요청을 보내는 단일 처리 경로를 사용한다.
- 정상 heartbeat 주기는 3초 유지. 요청 중 실시간 알림이 몰리면 후속 조회 하나로 합친다.
- 오류 재시도 간격은 3 → 6 → 12 → 24 → 최대 30초로 늘리고 성공 시 초기화한다.
- timestamp만 바뀐 멤버 알림은 동일 데이터를 다시 조회하지 않는다. 준비/대형/전투/ACK 변화는 계속 반영한다.
- Realtime의 `old`가 기본키만 담는 상황을 지원하며, 불완전한 알림은 보수적으로 재조회한다. 재구독 시 전체 동기화한다.
- 이전 방의 늦은 응답/실패 처리로 새 방 화면을 덮어쓰지 않도록 세션을 확인한다.
- 확정적인 접속/참가 권한 오류는 자동 요청과 자동 출발을 멈추고 재입장을 안내한다.
- 요청을 임의로 포기한 뒤 새 요청을 겹쳐 보내는 방식은 사용하지 않는다. 브라우저 요청 취소가 진행 중인 Edge/DB 실행 취소를 보장하지 않기 때문이다.

## 실제 PostgreSQL 검증

운영과 같은 PostgreSQL **17.6**을 별도 임시 폴더/임의 포트/`127.0.0.1`에 띄우고 가상 학생 데이터만 사용했다. 운영 DB에 부하 테스트를 하지 않았다.

- 기존 SQL 마이그레이션 50개를 원본 그대로 적용. Windows 로컬 환경에 없는 `pg_cron` 예약 마이그레이션만 제외했다.
- Supabase의 auth/realtime 플랫폼 스키마는 최소 테스트 대체물이며, 앱 DB 함수/테이블/트리거는 실제 마이그레이션이다. 관리형 API/Gateway/Auth/Realtime 전체를 재현한 테스트는 아니다.
- 운영 DB에서 읽은 관련 기존 함수 8개 본문 해시가 테스트 DB의 기존 함수와 전부 일치했다.
- 기존 코드에서 publish 및 question-ready와 heartbeat의 교착 **2건을 실제 `40P01`로 재현**했다.
- 수정 코드에서 양쪽 시작 순서를 포함한 **4가지 잠금 순서 모두 정상 커밋**. 대기 중인 heartbeat가 멤버 잠금을 선점하지 않는 것도 확인했다.
- 던전 **두 방/6명**의 준비 ACK+heartbeat, 결과 발행+heartbeat 동시 요청을 통과했다. 방별 이벤트 중복 방지/전투 상태/재시도 멱등성도 확인했다.
- 탈퇴 중 응답 대기, 비회원, null/정확한 제한 시각, 만료 관련 필드 보존, 함수 권한을 검증했다.
- 기존 채널 코드의 중복 저장과 잘못된 1채널 대기를 재현한 뒤 수정본에서 제거됐음을 확인했다.
- 기존/수정본의 정제된 외형 상태, 명단, 외형 변경분, 채팅, 전체 알림, 구버전 응답을 비교했다. 시간 필드를 제외하고 일치했다.
- 31명 동시 자동 입장: 10개 채널에 3명씩 우선 배치 후 31번째가 1채널의 4번째로 배치됐다.
- 7명 채널에 두 명이 동시에 입장: 한 명 성공, 한 명 정원 초과. 기존 참여자 유지 및 실패한 이동의 원래 채널 보존 확인.
- 구버전 heartbeat/채널 이동 동시 처리, 채널별 방송 권한, 비공개 함수/테이블 접근 차단, 잘못된 입력 거부 확인.
- 28명 가상 학생의 280회 병렬 채널 동기화 요청에서 SQL 오류가 없었다. **운영 28명 성능 보장 수치가 아니라 잠금/동시성 회귀 검사**다.
- 테스트 PostgreSQL은 종료했고, 임시 가상 DB 파일만 로컬 Temp에 남겨두었다.

5. 학생 로그인/문제집 조회, 채널 이동, 3명 준비/출발/전투/탈퇴/재입장, 채팅/전체 알림을 점검한다.
