# 육삼빌딩의 세계 프로젝트 점검 기록

작성일: 2026-07-04

## 한 줄 결론

새 기획을 시작할 수 있을 만큼 안정화되었지만, 아직 출시용 구조는 아닙니다. 특히 `game.js`에 남아 있는 패치 체인과 브라우저 수동 검증 부족이 다음 위험 요소입니다.

## 현재 확인한 안정 상태

전체 테스트 명령은 통과했습니다.

```powershell
powershell -NoProfile -ExecutionPolicy Bypass -File tools/run-baseline.ps1 all
```

통과한 검사:

- `baseline`
- `core-utils`
- `game-data`
- `quest-data`
- `patch-data`
- `refactor-health`
- `current-data`

이번 정리로 확인된 좋은 점:

- 데이터 일부가 `src/` 모듈로 분리되었습니다.
- 중복 최상위 함수 선언을 막는 검사가 추가되었습니다.
- 장비 착용 조건에서 직업과 레벨 조건을 함께 확인합니다.
- 엘리트 몬스터 렌더링이 유지되는지 검사합니다.
- 패치성 데이터 일부가 `src/patch-data.js`로 분리되었습니다.

## 현재 파일별 역할

- `index.html`: 화면 구조와 모달, 버튼, 캔버스입니다.
- `style.css`: UI 스타일과 배치입니다.
- `game.js`: 게임 실행의 중심입니다. 아직 너무 큽니다.
- `src/core-utils.js`: 공용 유틸 함수입니다.
- `src/game-data.js`: 기본 게임 데이터입니다.
- `src/quest-data.js`: 퀘스트 데이터입니다.
- `src/patch-data.js`: 후반 패치성 데이터입니다.
- `tests/refactor-health.test.mjs`: 리팩터링 중 다시 망가지기 쉬운 부분을 막는 안전망입니다.
- `tools/run-baseline.ps1`: 검사를 실행하는 도구입니다.

## 남은 중요 위험 1: `game.js` 패치 체인

`game.js`에는 v17부터 v35까지 이어진 패치 흐름이 남아 있습니다. 이 구조는 지금 당장 게임을 깨뜨리는 문제는 아니지만, 앞으로 기능을 추가할 때 가장 위험한 부분입니다.

위험한 이유:

- 같은 기능을 여러 버전 패치가 다시 정의할 수 있습니다.
- 뒤쪽 패치가 앞쪽 패치 동작을 몰래 바꿀 수 있습니다.
- 새 기능을 맨 아래에 또 붙이면 문제를 더 찾기 어려워집니다.
- 비슷한 함수 이름이 많아지면 어떤 함수가 실제로 쓰이는지 헷갈립니다.

작업 원칙:

1. `game.js` 맨 아래에 v36 패치를 새로 붙이는 방식은 피합니다.
2. 데이터 추가는 먼저 `src/` 데이터 파일로 분리합니다.
3. 계산만 하는 함수는 화면 코드와 분리합니다.
4. 화면 조작 코드는 마지막에 고칩니다.
5. 작은 단위로 수정하고 테스트를 자주 돌립니다.

2026-07-04 추가 진행:

- v35 스킬창 스타일을 `game.js` 런타임 스타일 주입에서 `style.css`로 흡수했습니다.
- `tests/refactor-health.test.mjs`에 v35 스킬창 스타일이 다시 JS 패치로 들어가지 않도록 막는 검사를 추가했습니다.
- 이 작업은 패치 체인을 완전히 제거한 것은 아니지만, 최신 패치의 UI 스타일 덩어리 하나를 메인 스타일시트로 옮긴 첫 번째 실제 감소 작업입니다.
- 펫 소환, 펫 상점 열기, 무기 강화 흐름에서 최신 함수가 예전 v27/v28/v31/v33 이름으로 다시 연결되던 alias 줄을 제거했습니다.
- 같은 alias가 다시 생기지 않도록 `tests/refactor-health.test.mjs`에 최신 흐름 고정 검사를 추가했습니다.
- `game.js` 크기 기준선은 의도적인 코드 삭제를 반영해 585,000바이트로 낮췄습니다.

## 남은 중요 위험 2: 문서와 실제 코드의 불일치

기존 문서는 글자가 깨져 있었고, 예전 버전 설명이 남아 있었습니다. 이 상태에서는 다음 Codex/ChatGPT 세션이 문서를 잘못 읽고 엉뚱한 방향으로 수정할 수 있습니다.

이번에 정리한 문서:

- `README.md`
- `docs/PROJECT_AUDIT.md`
- `docs/VIBE_CODING_GUIDE.md`

앞으로 문서에 꼭 적어야 하는 것:

- 현재 코드가 어디까지 정리되었는지
- 어떤 파일을 먼저 고쳐야 안전한지
- 어떤 작업은 아직 하지 말아야 하는지
- 테스트 명령은 무엇인지

## 아직 부족한 테스트

현재 테스트는 코드 구조와 데이터 안정성을 주로 확인합니다. 하지만 실제 브라우저에서 버튼을 누르고 캐릭터를 움직이는 테스트는 아직 없습니다.

추가하면 좋은 브라우저 테스트:

- 첫 화면이 열리는지
- 캐릭터 생성 후 게임 화면에 들어가는지
- 이동 키가 동작하는지
- 전투 화면이 열리는지
- 아이템/스킬 모달이 깨지지 않는지
- 콘솔 오류가 없는지

## 30명 동시 접속 목표에 대한 판단

현재 프로젝트는 로컬 브라우저 게임에 가깝습니다. 저장도 주로 `localStorage` 중심입니다.

30명 학생이 동시에 접속하려면 새 기획에서 아래 구조가 필요합니다.

- 서버
- DB
- 로그인 또는 학생 식별 방식
- 캐릭터 저장
- 문제 풀이 기록 저장
- 보상/강화 결과를 서버에서 판정하는 구조
- 필요하면 실시간 동기화

처음부터 너무 크게 만들 필요는 없습니다. 1차 온라인 목표는 “30명이 각자 접속해서 자기 캐릭터를 저장하고 이어서 플레이할 수 있는 구조”로 잡는 것이 현실적입니다.
