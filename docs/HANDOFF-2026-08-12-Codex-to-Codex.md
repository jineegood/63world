현재 3인 흐름:

- 방장이 방을 만들고 4자리 코드를 두 친구가 입력한다.
- 앞/가운데/뒤를 정하고 세 명이 준비하면 5초 뒤 출발한다.
- 같은 전문화 세 명은 `더 다양한 직업군으로 파티를 구성해야 합니다!`로 준비/출발이 막힌다.
- 학생마다 서로 다른 문제가 나오며, 세 화면이 모두 문제를 그렸다고 서버에 알려야 공통 30초가 시작된다.
- 친구 답을 기다릴 때만 `친구들의 문제 풀이를 기다리는 중…`, 서버 계산·연출 장벽은 `서버 대기중…`으로 표시한다.
- 방장이 결과를 한 번 계산해 서버에 발행하고 세 화면은 동일 이벤트를 재생한다.
- 몬스터, 기술 예고, 체력, 상태이상, 다음 라운드가 방 버전과 이벤트 순서로 동기화된다.
- 죽은 학생은 현재 몬스터 전투에서 행동하지 않고 쿨타임도 줄지 않는다. 다음 몬스터에서 HP 1로 부활한다.
- 보호막·기절·전투 임시 상태는 다음 몬스터로 가져가지 않는다.
- 한 명이 클리어 결과 확인을 먼저 눌러도 남은 두 명이 종료 장벽에 갇히지 않게 수정되어 있다.

던전 동기화에서 다시 건드리면 안 되는 핵심:

- 늦게 온 heartbeat/sync가 새 상태를 덮지 않도록 `room.version` 역행을 막는다.
- 문제 화면 준비 장벽(`ackQuestionReady`)과 전투 연출 완료 장벽(`ackPlayback`)은 서로 다른 역할이다.
- 화면마다 랜덤 몬스터/기술을 뽑지 않는다. 방의 `encounterIds`와 `patternSeed`를 공유한다.
- 방장 화면의 로컬 연출이 끝났다고 다른 두 명의 완료 확인 없이 다음 턴을 시작하지 않는다.
- 첫 조우에서 서버 `travel` heartbeat가 로컬의 `battle` 도착 상태를 되돌리는 race는 이미 수정됐다.
- 기존 테스트만 믿지 말고 동기화 변경은 가능하면 실제 3개 클라이언트 상태를 흉내 내는 통합 검사를 추가한다.

## 4. 던전 콘텐츠와 현재 밸런스

던전 몬스터는 총 17마리이며 `src/raid-rules.js`가 현재 기준이다. 과거 39마리 확장안은 폐기된 참고자료이므로 임의로 되살리지 않는다.

구간은 `1~10`, `11~20`, `21~30`, `31~40`, `41~50`, `51~60`, `61~63`의 7개다. 각 구간은 현재 정해진 몬스터 순서로 진행하며, 화면마다 따로 랜덤을 돌리지 않는다.

자리 피해 배율:

- 앞: 1.5배
- 가운데: 1.0배
- 뒤: 0.6배
- 단일 대상 추가 배율: 1.0배(과거 1.6배에서 제거)
- 전체 공격 배율: 0.5배
- 사망으로 자리가 당겨지면 **현재 위치**를 다시 계산해 피해를 적용한다.

던전 최초 클리어 보상(경험치/골드/빌딩):

- 1~10: `20 / 90 / 10`
- 11~20: `20 / 120 / 13`
- 21~30: `30 / 150 / 16`
- 31~40: `30 / 190 / 20`
- 41~50: `40 / 230 / 24`
- 51~60: `40 / 280 / 29`
- 61~63: `50 / 400 / 40`

보상과 해금 규칙:

- 각 구간 보상은 캐릭터당 최초 1회만 지급한다.
- `raid_reward_claims_v1` 영수증과 서버 트랜잭션으로 중복 지급을 막는다.
- 클라이언트의 오래된 저장이 서버 보상을 덮지 않도록 `raidRewardVersion` 보호가 있다.
- 클리어 층 해금은 `raid_progress_v1`과 `raidTopGroup`으로 보존되며, 방 만들기 화면에 `CLEAR!`가 표시된다.

추가 던전 규칙:

- Lv.11 이상 던전 몬스터는 기절이 걸려도 자기 턴에 즉시 깨어나며 로그가 나온다.
- 몬스터 기술 예고의 기술명은 모두 노란색 서식이다.
- 전투 세분화 로그에서 공격·자리·치명타·방어·보호막·회복 계산 근거를 볼 수 있다.
- 던전 포기 확인창은 서버 새로고침에 덮이지 않게 보호되어 있다.
- 교사 치트로 현재 던전 몬스터 즉시 처치, 던전 해금 상승, 던전 일시정지/재개가 가능하다.
- 일시정지 중에는 제한시간과 음악도 멈춘다.

## 7. 문제집/AI 기능의 현재 실제 상태

관리자 화면에서 OpenAI API를 직접 호출해 문제를 자동 생성하는 기능은 현재 없다.

현재 구현은:

1. 교사가 주제와 최대 20문제를 입력한다.
2. `ChatGPT에 넣을 문장 복사` 버튼으로 CSV 생성용 프롬프트를 복사한다.
3. ChatGPT 결과를 `엑셀 · CSV로 문제 추가` 칸에 붙여넣는다.

과거 `game.js`에 규칙 기반 `generateAiQuestions` 코드가 남아 있지만 현재 관리자 화면은 이를 호출하지 않는다. 새 대화에서 “AI가 바로 문제를 생성”하는 기능을 요청받으면 현재 프롬프트 복사 흐름과 혼동하지 말고 별도 서버 API/비용/키 보관 구조가 필요한 새 작업으로 본다.

## 9. 이 프로젝트의 지뢰밭

- `game.js`의 `const game`은 `window.game`이 아니다. 테스트에서는 기존 `window.__G` 연결이나 현재 harness 방식을 따른다.
- `showLoadingTransition` 콜백 직후 모달을 열면 뒤늦게 상태가 지워질 수 있다. 던전은 `LOADING_TAIL_MS`를 사용한다.
- 전투 중 모달 전체를 다시 그리면 체력바/연출 DOM이 끊긴다. 재생 중에는 값만 갱신한다.
- 몬스터가 죽자마자 상태에서 제거하면 마지막 로그·사망 연출·다음 이동이 끊길 수 있다.
- `confirmFormation`은 검사만 하는 함수가 아니라 실제 phase를 바꾼다. 검증에는 `validateFormation`을 쓴다.
- 소스는 CRLF일 수 있다. 정규식 테스트는 읽은 뒤 `replace(/\r\n/g,'\n')`로 정규화한다.
- 새 production 스크립트는 `index.html`, `tools/run-baseline.ps1`, 필요하면 `package.json`과 baseline 검사에 모두 등록한다.
- 공유 작업 폴더에 사용자 변경이 보이면 무조건 보존한다. 관련 없는 파일을 되돌리거나 `git reset --hard`를 쓰지 않는다.
- `docs/superpowers`의 오래된 설계/계획을 새 작업의 필수 절차로 사용하지 않는다. 제작자는 긴 사전 계획을 원하지 않는다.
