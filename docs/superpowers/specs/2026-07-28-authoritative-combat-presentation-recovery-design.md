# 서버 전투 연출·상태 동기화 복구 설계

작성일: 2026-07-28

## 목표

서버가 전투 결과를 안전하게 계산하는 현재 구조는 유지하면서, 서버 전환 전에 정상 동작하던 전투 로그·체력 변화·사망·보상·도망 연출의 순서를 복구한다.

이번 작업에서 해결할 문제는 다음과 같다.

- 서버가 계산한 피해를 화면이 먼저 적용한 뒤 연출이 같은 피해를 다시 적용하는 이중 피해
- 화면에서는 몬스터 HP가 0이지만 서버에서는 살아 있어 처치되지 않는 현상
- 공격과 피격 전에 체력바가 먼저 변하는 현상
- 전투가 끝나기 전에 경험치·골드·레벨·최대 체력 등이 먼저 HUD에 반영되는 현상
- 일부 오류가 모두 `전투 서버에서 안전하게 처리하지 못했습니다.`로 표시되는 현상
- 명진쌤 회복 훈련 공격의 치명타 피격 연출 부족
- 일반 전투가 시작될 때 맵 음악 대신 전투 전용 음악으로 바뀌는 동작
- 서버 전투에서 예전 도망 애니메이션과 도망 실패·반격이 사라진 상태

## 핵심 원칙

1. 전투 결과·피해량·보상·도망 성공 여부는 서버만 결정한다.
2. 브라우저는 서버 결과를 계산하지 않고 시간 순서에 맞게 보여주기만 한다.
3. 서버가 보낸 최종 상태는 연출이 끝날 때 한 번 적용해 화면 상태를 정확히 교정한다.
4. 서버 응답을 받았다는 이유만으로 HUD, 체력바, 경험치, 레벨을 먼저 바꾸지 않는다.
5. 예전 로컬 전투의 문구·소리·타격·쓰러짐·보상 순서를 재사용한다.

## 전투 한 턴의 처리 순서

1. 학생이 답을 제출한다.
2. 서버가 정답, 공격, 반격, 상태이상, 승패, 보상을 모두 계산한다.
3. 브라우저는 서버의 최종 캐릭터·세션 값을 `대기 상태`로 보관한다.
4. 브라우저는 턴 시작 직전의 화면 상태에서 서버 이벤트를 순서대로 재생한다.
5. 공격이나 피격이 실제로 보이는 순간에만 체력바와 데미지 숫자가 한 번 변한다.
6. 모든 로그와 연출이 끝나면 대기 중인 서버 최종 상태를 적용한다.
7. 계속 전투라면 다음 행동 메뉴를 연다.
8. 승리라면 쓰러짐과 승리 연출을 끝낸 후 전투창을 닫는다.
9. 전투창이 닫힌 뒤 경험치, 골드, 빌딩을 순서대로 보여준다.
10. 레벨업·최대 체력·현재 체력 변화도 전투 종료 시점에 반영한다.

이 방식으로 화면에서 재생한 값과 서버 최종 값이 미세하게 달라도 마지막에 서버 값으로 자동 교정된다.

## 승리·패배 처리

### 승리

- 서버 결과가 `victory`여도 공격 로그가 끝날 때까지 몬스터를 연출상 살아 있게 둔다.
- 마지막 타격 순간에 HP가 0이 된다.
- 전체 공격 로그가 끝난 다음 몬스터 쓰러짐 연출을 시작한다.
- 쓰러짐, 승리 안내, 전투창 종료 순서를 지킨다.
- 서버 캐릭터 상태는 전투창 종료 직전에 적용한다.
- 전투창 종료 후 경험치, 골드, 빌딩, 레벨업을 표시한다.

### 패배

- 마지막 몬스터 공격과 상태이상 피해를 모두 보여준다.
- 플레이어 HP가 0이 되는 순간을 표시한 뒤 패배 연출을 실행한다.
- 서버가 정한 마을 복귀·골드 손실·회복 상태를 패배 연출 종료 시 적용한다.

## 전투 오류 복구

- 요청 중에는 버튼을 잠가 같은 행동이 두 번 전송되지 않게 한다.
- 서버가 알려주는 공개 가능한 오류 코드를 각각 쉬운 한국어로 표시한다.
- 세션 번호나 문제 번호가 잠시 어긋난 경우 서버에서 현재 전투를 한 번 다시 불러온다.
- 복구에 성공하면 현재 체력과 문제를 맞추고 공격 메뉴로 돌아간다.
- 진행 중인 전투가 서버에 없으면 로컬 전투 상태를 정리하고 창을 닫는다.
- 알 수 없는 내부 오류는 학생에게 내부 정보나 정답을 노출하지 않는다.
- 진단을 위해 서버 로그에는 비밀번호, 토큰, 정답 없이 작업 종류와 안전한 오류 코드만 남긴다.

## 도망 복구

도망은 서버 전투의 새 행동으로 처리한다. 브라우저 난수나 별도 SQL 계산으로 판정하지 않는다.

- 플레이어 레벨이 몬스터 레벨과 같거나 높으면 성공 확률 80%
- 몬스터 레벨이 더 높으면 성공 확률 50%
- 보스는 도망 불가
- 성공하면 예전 2단계 후퇴 애니메이션을 재생한 뒤 전투 세션을 종료한다.
- 실패하면 해당 전투에서 도망을 다시 시도할 수 없다.
- 실패 직후 서버가 기존 몬스터 공격 공식으로 반격을 계산한다.
- 반격은 일반 몬스터 턴과 같은 소리, 타격, 보호막, 피해 숫자, 상태이상 연출을 사용한다.
- 도망 요청도 요청 ID와 세션 번호로 중복 실행을 방지한다.

## 음악

- 일반 전투에 들어가도 현재 숲·사막·늪 음악을 그대로 유지한다.
- 일반 전투가 끝날 때도 음악을 다시 시작하거나 처음부터 재생하지 않는다.
- 보스방과 최종 보스방은 맵 입장 때 선택된 보스 음악을 전투 중에도 유지한다.
- 기존 전투 전용 음원 파일은 삭제하지 않지만 자동 선택 대상에서는 제외한다.

## 명진쌤 회복 훈련 공격

`tut_healing_well` 퀘스트 수락 결과의 HP 1은 계속 서버가 저장한다.

화면은 다음 순서로 보여준다.

1. 대화창 닫기
2. 명진쌤 공격 효과음
3. 치명타 전용 효과음
4. 강한 화면 흔들림과 피격 시각 효과
5. 감소한 피해량 또는 HP 1 안내
6. 치유의 우물 안내

서버 상태 적용과 피격 연출의 타이밍을 맞춰 HUD가 먼저 HP 1로 바뀌지 않게 한다.

## 코드 구조

새 동작은 `game.js`에 더 큰 패치 덩어리를 추가하지 않는다.

- 전투 표시 상태와 최종 서버 상태 보관: `src/authoritative-combat-presentation-v3.js`
- 도망 판정과 반격 계산: 기존 `student-combat-v3` 서비스·규칙 모듈 확장
- 서버 오류 기록: Edge Function의 안전한 오류 기록 경계
- 기존 `src/combat-log-v3.js`: 서버 이벤트를 예전 전투 알림으로 번역하는 역할 유지
- `game.js`: 위 모듈을 연결하는 얇은 코드만 유지

## 검사

자동 검사에서 다음을 고정한다.

- 몬스터 HP 10에서 서버 최종 HP 5와 피해 이벤트 5를 받았을 때 화면도 5이며 0이 되지 않는다.
- 플레이어 피해도 같은 값이 두 번 적용되지 않는다.
- 타격 연출 전에 체력과 HUD가 변하지 않는다.
- 승리 공격의 전체 로그가 끝나야 몬스터가 쓰러진다.
- 전투창이 닫히기 전에는 경험치·골드·레벨업·최대 체력이 변하지 않는다.
- 연출 종료 후 화면 상태가 서버 최종 상태와 정확히 일치한다.
- 도망 확률, 실패 잠금, 실패 반격, 성공 애니메이션을 검증한다.
- 일반 전투에서는 맵 음악, 보스방에서는 보스 음악이 유지된다.
- 회복 훈련 공격에 치명타 소리와 피격 효과가 모두 연결된다.
- 오류 복구가 같은 공격을 다시 제출하지 않는다.
- 기존 전투 로그·효과·보안 검사를 모두 함께 실행한다.

## 배포

변경에는 브라우저 코드, Edge Function, 데이터베이스 마이그레이션이 포함될 수 있다.

1. 전체 자동 검사
2. 임시 계정으로 실서버 전투 시작·공격·승리·도망 성공·도망 실패 검사
3. 코드 커밋과 GitHub 푸시
4. Vercel 배포 확인
5. `student-combat-v3` 재배포
6. 필요한 마이그레이션 적용
7. 사용자가 실제 게임에서 최종 체감 확인

실서버 배포는 구현과 전체 검증이 끝난 뒤 사용자에게 다시 확인받고 진행한다.
