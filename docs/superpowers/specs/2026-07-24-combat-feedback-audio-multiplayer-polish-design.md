# 전투 타격감·음악·접속·안내 개선 설계

## 목표

전투의 모든 실제 피격에 일관된 시각·청각 피드백을 제공하고, 보호막 피해·전투 음악·보상 안내·치유 우물·퀘스트 가독성·실시간 접속을 안정화한다. 몬스터 처치 후 이동 불가 버그도 같은 상태 전환 계층에서 해결한다.

## 범위와 원칙

- 일반 피격은 맞은 대상만 짧게 흔든다.
- 치명타는 대상 흔들림과 기존 화면 전체 흔들림을 함께 사용한다.
- 플레이어의 기본 공격 빗나감 확률은 타격마다 정확히 10%로 유지한다.
- 보스방과 최종 보스방에서는 맵 입장부터 전투 종료까지 기존 보스 음악을 유지한다.
- GitHub 푸시, Vercel 배포, Supabase 설정 변경은 이번 구현 범위에 포함하지 않는다.
- 기존 사용자 음원 두 개를 정식 에셋으로 등록하되 원본 파일은 변경하지 않는다.

## 1. 피격 피드백과 보호막

전투 효과 처리기가 피해 적용 전후의 HP와 보호막을 함께 비교하여 다음 세 값을 만든다.

- `shieldDamage`: 실제로 감소한 보호막
- `hpDamage`: 실제로 감소한 HP
- `fullyBlocked`: 원래 피해가 1 이상이며 `shieldDamage > 0`, `hpDamage === 0`

플레이어와 몬스터 모두 실제 피해가 발생한 순간 맞은 전투 배우에게 짧은 `actor-hit-shake` 효과를 준다. 치명타일 때는 이 효과 외에 기존 전체 화면 흔들림을 유지한다.

보호막 감소 숫자는 보호막 생성 숫자와 구분한다.

- 보호막 생성: 기존 `+숫자`
- 보호막 피해: 회색 또는 청회색 `-숫자`
- HP 피해: 기존 붉은색 `-숫자`

한 공격이 보호막과 HP를 모두 깎으면 보호막 감소 숫자와 HP 감소 숫자를 모두 표시한다. 피해 전부를 보호막이 막은 경우에만 `assets/3. 보호막으로만 다 데미지 막혔을때 소리.mp3`를 한 번 재생한다. 일부 피해가 HP까지 들어오면 이 전용 소리를 재생하지 않는다.

## 2. 전투 음악

`assets/1. 전투씬 음악.wav`를 반복 재생되는 `battleBgm`으로 오디오 목록에 등록한다.

음악 선택 규칙은 하나의 함수에서 결정한다.

1. `bossRoom` 또는 `finalBossRoom`: 항상 기존 `bossBgm`
2. 일반 맵에서 전투 중: `battleBgm`
3. 전투가 아니면: 현재 마을·숲·사막·늪 음악

전투 시작, 정상 처치, 도망, 사망, 강제 전투 종료가 모두 같은 음악 동기화 함수를 호출한다. 음악 객체는 매번 새로 만들지 않고 재사용하며, 선택되지 않은 파일은 일시정지한다. 일반 전투가 끝나면 현재 장소 음악이 처음부터가 아니라 일시정지된 위치에서 다시 이어진다.

## 3. 보상 안내와 이동 불가 버그

몬스터·퀘스트 보상은 실제 자원 지급과 저장을 즉시 완료한 뒤 표시만 순차적으로 진행한다.

- EXP: 보라색, 1초
- Gold: 노란색, 1초
- 빌딩: 분홍색, 1초

표시 항목이 시작될 때마다 기존의 짧은 합성 보상음을 재생한다. 빌딩 보상이 없으면 빌딩 단계는 생략한다.

현재 이동 불가의 원인은 몬스터 처치 함수가 `modalState`를 `cinematic/pause`로 설정한 뒤, 독립형 보상 표시가 그 상태를 해제하지 않는 데 있다. 보상 오버레이는 게임 일시정지 상태를 소유하지 않게 하고, 전투 종료 시 전투 모달을 닫은 직후 `modalState`와 전투 잠금을 명시적으로 정상화한다. 레벨업·전문화처럼 실제 모달을 소유하는 흐름은 덮어쓰지 않는다.

## 4. 치유의 우물

사냥터 입구 우물은 입구 포탈의 정면 통로를 벗어나 위쪽 옆 공간으로 이동한다. 상위 몬스터 구역 앞 우물도 주변 통로를 막지 않는지 좌표를 검증한다.

모든 사냥터 우물에 반지름 약 40픽셀의 원형 충돌을 추가한다. 상호작용 거리는 충돌 반지름보다 넓게 유지하여, 플레이어가 우물에 닿지 않고도 `E`로 사용할 수 있게 한다.

## 5. 빗나감

플레이어의 각 공격 타격은 독립적으로 10% 빗나감 판정을 받는다. 다단 공격은 타격 수만큼 독립 판정하므로 한 행동에서 빗나감이 여러 번 보일 수 있다.

확률 자체는 변경하지 않는다. 경계값 테스트를 추가하여 난수값이 `0.10` 미만일 때만 빗나가고 `0.10` 이상이면 적중하도록 고정한다. 오답 절반 공격은 현재 초보자 완화 설계대로 빗나감 없이 적용한다.

## 6. 동시접속

현재 `cloud-config.js`의 URL은 REST 경로(`/rest/v1/`)까지 포함하고 있으나, 멀티플레이어는 이를 프로젝트 기본 주소로 가정해 WebSocket 주소를 조합한다. 그 결과 실시간 주소가 잘못 생성될 수 있다.

멀티플레이어 전용 URL 정규화 함수가 다음 입력을 모두 동일한 프로젝트 기본 주소로 변환한다.

- `https://PROJECT.supabase.co`
- `https://PROJECT.supabase.co/`
- `https://PROJECT.supabase.co/rest/v1`
- `https://PROJECT.supabase.co/rest/v1/`

정규화된 주소로 Supabase Realtime WebSocket에 연결하고 위치·맵·외형·이름·채팅을 송수신한다. 서로 다른 이름의 두 브라우저 세션이 같은 맵에서 서로를 표시하고 채팅을 주고받는 시나리오를 자동 검사한다. 같은 이름은 자기 자신으로 간주하므로 두 기기 검사는 서로 다른 캐릭터 이름을 사용한다.

로컬 코드가 수정되어도 공개 Vercel 앱은 다시 배포하기 전까지 갱신되지 않는다.

## 7. 퀘스트 강조

퀘스트 원문을 직접 HTML로 신뢰하지 않는다. 먼저 전체 문장을 이스케이프한 뒤, 게임이 관리하는 용어만 안전한 강조 태그로 감싼다.

- 노란색 굵게: `N키`, `E키`, 기타 조작키, 장소, 몬스터 이름, 해야 할 행동
- 초록색 굵게: 보상, 획득, 완료, 지급 자원과 수량

퀘스트 설명, 이야기 페이지, 완료 대사에 동일한 렌더러를 사용한다. 일반 사용자 채팅과 관리자 입력에는 적용하지 않는다. 기존 퀘스트 데이터 원문은 수정하지 않아 저장 호환성을 유지한다.

## 8. 검증

다음 동작을 자동 검사한다.

- 플레이어와 몬스터의 일반 피격마다 대상 흔들림 발생
- 보호막 전부 방어, 일부 방어, 보호막 없음의 숫자·소리 분기
- 일반 전투 음악 시작과 지역 음악 복귀
- 보스방 음악이 전투 중에도 유지
- EXP·Gold·빌딩 안내의 순서, 1초 유지, 색상, 단계별 효과음
- 몬스터 처치 후 이동 및 입력 가능
- 우물 좌표, 충돌, 상호작용 거리
- 타격별 빗나감 확률 경계값
- Supabase URL 정규화와 두 세션 위치·채팅 송수신
- 퀘스트 HTML 이스케이프와 중요 용어 강조

집중 검사가 통과한 뒤 전체 `npm test`를 실행한다. 사용자 음원 이외의 비밀키·배포 설정·보안 전환 값은 변경하지 않는다.
