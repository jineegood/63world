# 63월드 서버 권위형 보안 전환 설계

## 1. 목표

63월드의 성장, 재화, 아이템, 스킬, 전투, 퀘스트와 PvP 결과를 학생 브라우저가 아니라 Supabase 서버가 결정한다. 학생은 정상적인 게임 행동을 요청할 수 있지만 저장된 결과를 직접 덮어쓸 수 없다.

출시 전 테스트 단계이므로 기존 `player_profiles_v2.data`를 신뢰 데이터로 변환하지 않는다. 새 구조를 만든 뒤 테스트 캐릭터를 초기화하고, 인증 계정은 필요에 따라 유지한다.

## 2. 설계 원칙

- 학생 브라우저에서 받은 숫자는 결과가 아니라 요청으로 취급한다.
- 서버는 `auth.uid()`로 행동 주체를 결정하고 요청의 `userId`를 신뢰하지 않는다.
- 경험치, 골드, 빌딩, 아이템, 강화, 스킬, 퀘스트, 전투와 승패는 학생이 직접 수정할 수 없다.
- 외모, 음량, 키 설정처럼 경쟁 결과에 영향을 주지 않는 설정만 학생이 직접 저장할 수 있다.
- 모든 재화 변경은 한 데이터베이스 트랜잭션에서 처리한다.
- 같은 요청이 재전송되어도 한 번만 적용되도록 `request_id`를 사용한다.
- 서버가 채점하기 전에는 문제 정답을 학생에게 보내지 않는다.
- 네트워크가 끊긴 동안에는 중요한 보상과 구매를 로컬에서 확정하지 않는다.
- 빈번한 행동은 Edge Function 대신 Postgres RPC를 사용해 무료 한도를 보호한다.

## 3. 전체 전환 프로그램

이 작업은 독립적으로 검증 가능한 여섯 단계로 나눈다. 각 단계는 별도 구현 계획과 테스트를 가진다.

1. **서버 권위 저장 기반**
   - 서버 전용 성장 상태, 인벤토리, 스킬, 퀘스트, 요청 영수증과 보안 기록을 만든다.
   - 학생의 기존 `player_profiles_v2` 직접 수정 경로를 게임에서 제거한다.
   - 새 캐릭터 생성과 로그인 로드를 서버 RPC로 전환한다.
2. **경제·장비·스킬**
   - 상점 구매, 장착, 강화, 전문화와 스킬 습득을 서버 RPC로 전환한다.
3. **일반 전투·문제**
   - 서버가 전투 세션과 공개 문제를 만들고 정답을 채점한다.
   - 서버가 피해, 처치와 보상을 확정한다.
4. **퀘스트**
   - 전투, 구매, 강화 등 서버가 확인한 사건만 퀘스트 진행에 반영한다.
   - 퀘스트 완료와 보상을 한 트랜잭션으로 처리한다.
5. **PvP 통합**
   - PvP 스냅샷을 새 서버 권위 상태에서만 만든다.
   - 기존 브라우저 저장값은 얼굴 표시 이외의 승패 계산에 사용하지 않는다.
6. **무료 한도형 실시간 이동**
   - 위치와 채팅을 WebRTC 데이터 채널로 직접 전달한다.
   - Supabase는 연결 신호와 실패 시 저빈도 대체 경로에만 사용한다.

본 문서가 확정하는 첫 구현 범위는 1단계다. 2~6단계는 1단계의 인터페이스를 사용하며 각 단계 시작 전에 세부 계획을 작성한다.

## 4. 1단계 데이터 구조

### `player_core_v3`

학생당 한 행을 가진다.

- `user_id uuid primary key`
- `display_name text`
- `class_name text`
- `spec text nullable`
- `level integer`
- `exp integer`
- `gold integer`
- `building integer`
- `current_hp integer`
- `current_map text`
- `revision bigint`
- `created_at`, `updated_at`

학생에게 `SELECT`만 허용한다. `INSERT`, `UPDATE`, `DELETE`는 모두 회수한다.

### `player_inventory_v3`

아이템 인스턴스마다 한 행을 가진다.

- `id uuid primary key`
- `user_id uuid`
- `item_definition_id text`
- `enhancement_tier integer`
- `equipped_slot text nullable`
- `grant_source text`
- `created_at`, `updated_at`

학생은 자기 행만 읽을 수 있고 직접 수정할 수 없다.

### `player_skills_v3`

- `user_id uuid`
- `skill_id text`
- `rank integer`
- `(user_id, skill_id)` 기본키

스킬 포인트 예산과 직업·전문화 조건은 서버 함수가 검사한다.

### `player_quests_v3`

- `user_id uuid`
- `quest_id text`
- `status text`
- `progress integer`
- `accepted_at`, `completed_at`
- `(user_id, quest_id)` 기본키

### `player_preferences_v3`

외모, 음량, 키 설정과 UI 안내 확인 여부만 저장한다. 학생은 자기 행을 수정할 수 있지만 허용된 키와 크기를 DB 제약으로 제한한다. 코스튬 소유권, 능력치, 위치 좌표와 재화는 이 테이블에 넣지 않는다.

### `game_action_receipts_v3`

`(user_id, request_id)`를 유일하게 저장해 중복 보상을 막는다. 응답 요약과 생성 시간을 저장하며 7일이 지난 일반 영수증은 정리한다.

### `security_events_v3`

유효하지 않은 아이템, 초과 스킬 포인트, 과도한 호출, 권한 위반과 상태 충돌만 기록한다. 일반 이동과 정상 행동은 기록하지 않는다. 관리자는 최근 기록을 조회할 수 있고 30일 후 정리한다.

## 5. 1단계 서버 인터페이스

### `create_student_character_v3`

- 인증된 학생에게 캐릭터가 없을 때 한 번만 생성한다.
- 서버가 직업별 초기 능력치, 초기 장비와 재화를 넣는다.
- 이름은 인증 계정의 기존 표시 이름과 일치시킨다.
- 같은 요청을 반복해도 기존 캐릭터를 반환한다.

### `load_student_game_v3`

- 학생 자신의 코어, 인벤토리, 스킬, 퀘스트와 환경설정을 한 번에 반환한다.
- 정답, 다른 학생의 비공개 데이터와 관리자 데이터는 포함하지 않는다.
- 응답에는 `revision`이 포함된다.

### `save_student_preferences_v3`

- 외모, 음량, 키 설정과 튜토리얼 확인값만 허용한다.
- 재화나 성장 필드가 섞이면 전체 요청을 거부하고 보안 기록을 남긴다.

### `transition_student_map_v3`

- 허용된 맵 이동 그래프와 해금 조건을 검사한다.
- 좌표를 권위 데이터로 저장하지 않는다.
- `current_map`만 서버가 갱신하며 이후 상점, 전투와 PvP의 장소 조건에 사용한다.
- 마을 귀환은 항상 허용하되 보스전 등 잠금 상태는 이후 전투 단계에서 추가 검사한다.

### 관리자 인터페이스

기존 교사 인증을 재사용해 테스트 캐릭터 초기화, 학생 상태 조회와 보안 기록 조회를 제공한다. 학생용 함수와 관리자용 함수는 분리한다.

## 6. 이후 전투와 문제의 권위 경계

현재 `shared_state_v2` 문제집은 학생이 정답까지 읽을 수 있으므로 일반 전투 서버화 단계에서 분리한다.

- 공개 문제: 문제 ID, 질문, 선택지만 학생에게 전달
- 비공개 문제: 정답과 채점 규칙은 서버만 읽음
- 전투 시작: 서버가 맵, 몬스터 종류, 호출 속도와 진행 중 세션을 검사
- 답 제출: 서버가 채점하고 피해와 다음 상태를 계산
- 처치 보상: 전투 종료와 동시에 서버 트랜잭션으로 지급
- 클라이언트 애니메이션: 서버 결과를 표현할 뿐 결과를 만들지 않음

좌표는 실시간 표현 정보이므로 서버 전투 보상의 증거로 사용하지 않는다. 서버는 허용된 맵, 전투 세션, 문제 정답과 호출 제한을 조합해 비정상적인 자동 사냥을 막는다.

## 7. 실시간 이동과 무료 한도

현재 220ms마다 Supabase Broadcast로 위치를 전송하는 구조는 제거 대상이다. Supabase는 Broadcast 한 건과 각 구독자 수신을 모두 메시지로 계산하므로 동시 28명에서는 무료 월 200만 메시지를 짧은 시간에 넘을 수 있다.

새 구조:

- 같은 방 학생끼리 WebRTC 데이터 채널을 연결한다.
- 위치는 움직일 때만 초당 최대 5회 작은 패킷으로 보낸다.
- 수신 측은 보간법으로 부드럽게 표시한다.
- Supabase Realtime은 사용자별 신호 채널의 offer/answer/ICE와 입퇴장 알림에만 사용한다.
- 연결 실패 시 2초 간격의 압축 위치 스냅샷을 REST/RPC로 교환한다.
- 실패 대체 경로는 화면 표시 전용이며 보상과 상호작용 판정에 사용하지 않는다.
- 채널과 타이머는 로그아웃, 새로고침과 맵 이탈 시 반드시 정리한다.

동시 28명, 주 4시간을 기준으로 자동 예산 테스트를 둔다.

- Edge Function: 월 10만 회 이내 목표, 무료 한도 50만 회
- Supabase Realtime: 월 50만 메시지 이내 목표, 무료 한도 200만 메시지
- DB 크기: 250MB 이내 경고, 무료 읽기 전용 전환선 500MB
- Egress: 월 3GB 이내 목표, 무료 비캐시 전송 5GB
- Realtime 동시 연결: 40 이하 목표, 무료 한도 200

Vercel은 정적 파일 배포만 담당한다. 게임 실행은 OpenAI 또는 다른 AI API를 호출하지 않으므로 학생 사용으로 AI 토큰이 소모되지 않는다.

## 8. 오류와 복구

- 서버 응답 전에는 구매, 강화, 보상과 스킬 습득을 확정 표시하지 않는다.
- 네트워크 오류에는 “저장되지 않았음”을 분명히 표시하고 같은 `request_id`로 안전하게 재시도한다.
- `revision` 충돌 시 최신 상태를 다시 불러와 화면을 맞춘다.
- DB 트랜잭션이 실패하면 관련 재화와 아이템 변경을 모두 취소한다.
- WebRTC 실패는 게임 진행 실패가 아니라 저빈도 위치 공유로 전환한다.
- 서버가 사용 불가능할 때는 캐릭터 조회와 설정 변경 외의 성장 행동을 잠시 막는다.

## 9. 보안 정책

- 모든 학생 RPC는 JWT와 `auth.uid()`를 확인한다.
- 서비스 역할 키는 Edge Function과 서버 환경에서만 사용하며 브라우저 번들에 넣지 않는다.
- `security definer` 함수는 `search_path = ''`와 명시적 스키마를 사용한다.
- 학생 역할에서 권위 테이블의 직접 쓰기 권한을 회수한다.
- 관리자 함수는 기존 `teacher_roles_v2` 검사를 재사용한다.
- 요청 크기, 문자열 길이, 숫자 범위와 호출 빈도를 서버에서 제한한다.
- 보상과 소비 함수는 행 잠금 또는 원자적 조건 갱신을 사용한다.
- PvP 승패, 문제 정답과 행동 영수증은 학생이 직접 삽입하거나 수정할 수 없다.

## 10. 테스트와 완료 기준

각 단계는 테스트를 먼저 작성하고 실패를 확인한 뒤 구현한다.

- RLS: 학생이 권위 테이블을 직접 수정하지 못함
- 신원: 다른 `userId`를 보내도 항상 `auth.uid()`만 사용
- 원자성: 구매·강화 실패 시 재화와 아이템이 함께 원복
- 중복 방지: 같은 `request_id`를 반복해도 결과가 한 번만 적용
- 범위 검사: 음수 재화, 존재하지 않는 아이템, 초과 스킬과 잘못된 맵 이동 거부
- 정답 비공개: 학생 응답과 Realtime 행에 정답이 없음
- 동시성: 두 기기에서 같은 계정으로 소비해도 잔액이 음수가 되지 않음
- 복구: 네트워크 재시도와 `revision` 충돌 후 서버 상태로 수렴
- 멀티플레이: 28개 모의 세션에서 WebRTC 신호량과 대체 경로 예산 통과
- 회귀: 기존 일반 전투, 퀘스트, 상점, 관리자와 PvP 테스트 통과

1단계 완료 기준은 신규 계정 생성·로그인·캐릭터 로드·환경설정 저장·허용된 맵 전환이 v3 서버 상태로 동작하고, 학생이 성장값을 직접 수정할 수 없으며, 기존 게임은 읽기 어댑터를 통해 v3 상태를 표시하는 것이다.

## 11. 배포와 데이터 처리

- 로컬 테스트와 Supabase 로컬/검증 프로젝트에서 먼저 실행한다.
- 운영 Supabase에는 사용자의 별도 승인 전까지 배포하지 않는다.
- 기존 인증 계정은 유지할 수 있지만 `player_profiles_v2` 테스트 캐릭터는 v3 권위 데이터로 자동 복사하지 않는다.
- 전환 시 관리자 화면에서 테스트 캐릭터 초기화를 명시적으로 실행한다.
- GitHub 푸시와 Vercel 배포는 전체 단계 검증 후 사용자가 요청할 때 수행한다.

## 12. 비목표

- 이동 좌표를 서버에서 프레임 단위로 시뮬레이션하지 않는다.
- 오프라인 상태에서 경험치나 아이템을 획득하게 하지 않는다.
- 무료 한도를 위해 보안 검사를 생략하지 않는다.
- 이번 1단계에서 상점, 전투, 퀘스트와 PvP 계산을 임시로 절반만 서버화하지 않는다. 해당 기능은 각 후속 단계에서 한 경계를 통째로 전환한다.
