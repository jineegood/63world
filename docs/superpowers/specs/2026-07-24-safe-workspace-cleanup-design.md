# 63world 안전 폴더 정리 설계

## 목적

프로젝트 최상위 폴더에서 GitHub에 올릴 필요가 없는 백업과 작업 결과물을
한 폴더에 모아, 비개발자도 실제 앱 파일과 임시 자료를 쉽게 구분할 수 있게 한다.

## 정리 범위

새 폴더 `작업자료`를 만들고 다음 두 폴더를 이동한다.

- `backups` → `작업자료/백업`
- `outputs` → `작업자료/작업결과`

두 폴더는 현재 Git에서 제외된 자료이며, 앱 실행에 직접 사용되지 않는다.

## 그대로 두는 항목

- `assets`, `data`, `src`, `supabase`, `vendor`: 앱 실행 파일
- `docs`, `tests`, `tools`, `시트`: Git으로 관리하는 개발 자료
- `node_modules`: 개발 도구가 정해진 위치에서 찾는 설치 폴더
- `.codex_work`, `.superpowers`, `.agents`: 작업 도구가 정해진 위치에서 사용할 수 있는 숨김 폴더
- 최상위 파일: 현재 Git으로 관리하거나 앱 실행에 필요한 파일

## Git 설정

`.gitignore`에 `작업자료/`를 추가하여 그 안의 모든 자료가 GitHub에 올라가지 않게 한다.
기존의 `backups/`, `outputs/` 제외 규칙도 남겨 두어 해당 폴더가 다시 생겨도 안전하게
Git에서 제외되도록 한다.

## 안전 조건

- 이동 전 원본 폴더와 새 위치를 정확히 확인한다.
- 새 위치에 같은 이름의 폴더가 이미 있으면 덮어쓰지 않고 중단한다.
- 파일을 삭제하지 않는다.
- Git이 관리 중인 파일은 이동하지 않는다.

## 확인 방법

1. `작업자료/백업`과 `작업자료/작업결과`의 파일 수가 이동 전과 같은지 확인한다.
2. 원래 위치의 `backups`, `outputs`가 사라졌는지 확인한다.
3. `git status`에서 예상한 `.gitignore`와 문서 변경 외의 손실이 없는지 확인한다.
4. 전체 테스트를 실행해 앱 동작에 영향이 없는지 확인한다.
