# 63월드 PvP·클릭 이동·튜토리얼 강조 설계

## 목적

학생들이 마을에서 친구의 캐릭터 정보를 확인하고 부담 없이 대전을 신청할 수 있는
실시간 PvP를 추가한다. PvP에서는 경험치·골드·아이템을 잃거나 얻지 않고 승리와 패배만
캐릭터 기록에 남긴다. 함께 왼쪽 클릭 이동을 지원하고, 최초 튜토리얼의 중요 표현을
퀘스트와 같은 초록색 굵은 글씨로 강조한다.

## 확정된 플레이 원칙

- PvP는 마을에 있는 학생끼리만 신청하고 시작할 수 있다.
- 레벨, 장비, 스킬, 전문화 효과는 평소 능력치를 그대로 사용한다.
- PvP 시작 시 양쪽의 임시 전투 HP만 최대치로 만든다.
- 월드의 원래 HP와 경험치, 골드, 빌딩, 아이템은 PvP로 변경하지 않는다.
- 결과로 서버가 관리하는 승리 또는 패배 기록만 정확히 한 번 증가시킨다.
- 매 라운드 두 학생은 같은 문제를 동시에 20초 동안 푼다.
- 먼저 제출해도 공격 순서는 정해지지 않으며 상대 제출 또는 제한 시간을 기다린다.
- 둘의 풀이가 끝난 뒤 매 라운드 양쪽이 30면체 주사위를 굴린다.
- 높은 숫자의 학생이 선공하며 동률이면 서버가 자동으로 재굴림한다.
- 선공 공격으로 후공의 HP가 0이 되면 후공 공격은 실행하지 않는다.

## 1. 시스템 구성

### 브라우저 게임

브라우저는 다음 역할만 담당한다.

- 마을의 원격 캐릭터 표시와 오른쪽 클릭 대상 판정
- 안전한 공개 프로필과 승패 기록 표시
- 대전 신청, 수락, 거절, 답안·행동 제출, 항복 요청
- 서버가 확정한 문제, 주사위, 공격 순서와 피해 결과의 연출
- 재접속 시 서버 경기 상태를 다시 받아 화면 복원
- 왼쪽 클릭 이동 경로 계산과 월드 이동

브라우저가 계산한 주사위, 피해량 또는 승패 값은 최종 결과로 신뢰하지 않는다.

### Supabase

현재 사용 중인 Supabase 안에 PvP 전용 테이블, 참가자 제한 정책과 서버 함수를 추가한다.
별도의 상시 게임 서버는 운영하지 않는다. 중요한 입력은 로그인 토큰을 확인하는
Supabase Edge Function 또는 동등한 서버 함수만 변경할 수 있다.

서버는 다음 역할을 담당한다.

- 학생의 마을 접속 여부와 대전 가능 상태 확인
- 신청 생성·수락·거절·만료
- 현재 활성화된 공용 문제집에서 같은 문제 한 개 선택
- 답안과 행동을 상대에게 숨긴 채 각각 한 번만 접수
- 20초 마감, 정답 판정, 오답·시간 초과의 50% 공격 적용
- 양쪽 30면체 주사위 생성과 동률 재굴림
- 기존 직업·전문화·스킬 규칙에 맞는 라운드 결과 확정
- 선공 처치 시 후공 행동 취소
- 항복, 접속 종료, 재접속과 최종 승패 처리
- 승패 기록의 원자적이고 중복 없는 갱신

### 기존 멀티플레이와의 관계

현재 Supabase Realtime Broadcast 기반 위치·채팅 기능은 유지한다. 원격 캐릭터 방송에
서버가 식별할 수 있는 공개 참가자 식별자, PvP 가능 상태와 코스튬 외형을 추가한다.
실제 경기 상태는 휘발성 방송 메시지가 아니라 Supabase 경기방에 저장하고 Realtime으로
두 참가자에게 전달한다.

## 2. 서버 데이터 경계

테이블은 `pvp_records_v1`, `pvp_presence_v1`, `pvp_invites_v1`, `pvp_matches_v1`,
`pvp_round_inputs_v1`, `pvp_match_events_v1`로 분리한다. 모든 변경 요청은
`pvp-match-v1` Edge Function을 통과하며 책임은 다음과 같다.

### PvP 기록

- 로그인 사용자 ID를 기준으로 한 행당 `wins`, `losses`를 보관한다.
- 게임의 캐릭터 프로필 화면에서는 이 값을 캐릭터 기록으로 표시한다.
- 학생 클라이언트에는 읽기만 허용하고 직접 수정 권한은 주지 않는다.
- 경기 종료 서버 함수만 승자 1승과 패자 1패를 하나의 작업으로 갱신한다.

### 신청

- 신청자, 대상자, 생성 시각, 20초 만료 시각과 상태를 보관한다.
- 같은 두 학생의 중복 신청과 한 학생의 다중 활성 신청을 막는다.
- 대상자만 수락 또는 거절할 수 있다.
- 마을 밖, 오프라인, 다른 경기 중인 대상에게는 신청을 만들지 않는다.

### 경기

- 참가자 두 명, 임시 전투 능력치 스냅샷, 현재 임시 HP, 라운드 번호, 단계, 마감 시각,
  접속 상태, 최종 결과와 상태 효과를 보관한다.
- PvP 능력치는 수락 시점의 저장된 캐릭터 레벨·장비·스킬·전문화를 사용한다.
- 숫자 범위와 장비·스킬 식별자를 서버에서 검증한다.
- 월드 플레이어 데이터의 HP는 읽거나 덮어쓰지 않고 PvP 임시 HP를 별도로 사용한다.

### 비공개 라운드 입력

- 각 참가자의 행동, 답안과 제출 시각을 별도 비공개 영역에 보관한다.
- 상대방과 일반 학생은 직접 읽을 수 없다.
- 두 입력이 모이거나 서버 시각이 마감에 도달한 뒤에만 판정 결과를 공개한다.
- 중복 제출은 첫 유효 제출만 인정한다.

### 공개 경기 이벤트

- 문제의 정답을 제외한 문제 내용과 선택지
- 양쪽 제출 대기 상태
- 판정 후 정답, 각 학생의 정오답
- 주사위 결과와 재굴림 여부
- 선공·후공, 피해·치유·보호막·상태 효과, 처치와 승패

각 이벤트는 일련번호를 가져 새로고침이나 재접속 후에도 같은 애니메이션을 중복 적용하지
않는다.

## 3. 프로필과 대전 신청

### 프로필 열기

- 같은 마을 화면에 보이는 다른 학생을 오른쪽 클릭하면 브라우저 기본 메뉴 대신 프로필을 연다.
- 캐릭터가 아닌 바닥을 오른쪽 클릭하면 게임이 가로채지 않는다.
- 겹친 캐릭터가 있으면 클릭 지점에 가장 가까운 캐릭터 한 명을 선택한다.

### 공개 정보

- 캐릭터 이름
- 레벨
- 직업과 전문화
- 승리와 패배
- 현재 얼굴, 머리 장비, 얼굴에 보이는 장비와 코스튬

비밀번호, 이메일, 내부 토큰, 전체 인벤토리와 비공개 저장 데이터는 노출하지 않는다.

### 얼굴 초상화

기존 캐릭터 렌더러를 별도 작은 캔버스에서 확대 실행한다. 머리와 얼굴 주변을 원형으로
잘라 프로필에 표시한다. 상대가 방송한 안전한 외형·장비·코스튬 정보로 그리므로 월드에서
보이는 모습과 일치한다. 장비 이름을 단순히 나열하는 것이 아니라 실제 착용 모습이
초상화에 반영되어야 한다.

### 대전 신청

- 양쪽이 마을에 있고 온라인이며 다른 전투·대화·상점·PvP에 들어가 있지 않을 때만
  `대전 신청` 버튼을 활성화한다.
- 대상에게 신청자 얼굴과 이름이 있는 수락·거절 창을 표시한다.
- 20초 동안 응답이 없으면 자동 취소한다.
- 거절과 만료는 승패에 영향을 주지 않는다.

## 4. 경기 시작과 라운드 흐름

### 시작

수락이 완료되면 두 브라우저가 동일한 경기 ID로 PvP 화면을 연다. 서버는 양쪽 능력치를
스냅샷으로 만들고 임시 HP를 각각 최대치로 설정하며 스킬의 전투 시작 상태를 초기화한다.
활성 문제집에 유효한 문제가 하나도 없으면 신청을 취소하고 이유를 안내한다.

### 문제와 행동 제출

1. 서버가 활성 문제집에서 같은 문제를 한 개 선택한다.
2. 양쪽에 같은 문제와 동일한 20초 마감 시각을 전달한다.
3. 각 학생은 기본 공격 또는 사용 가능한 액티브 스킬과 답을 제출한다.
4. 먼저 제출한 학생은 정답 여부 대신 `상대가 문제를 푸는 중이에요. 잠시 기다려 주세요!`
   안내만 본다.
5. 두 학생이 모두 제출하거나 20초가 끝나면 서버가 라운드를 잠근다.
6. 미제출은 시간 초과 오답으로 처리하고 선택된 행동의 50% 효과를 적용한다. 행동도
   선택하지 않았다면 기본 공격을 사용한다.
7. 정답과 양쪽 결과를 동시에 공개한다.

### 주사위와 공격

1. 서버가 각 참가자에게 1부터 30까지의 값을 생성한다.
2. 동률이면 두 값 모두 다시 생성하고 재굴림 이벤트를 남긴다.
3. 클라이언트는 전투 화면 중앙에서 두 30면체 주사위 애니메이션을 동시에 재생한다.
4. 숫자를 크게 보여주고 선공 학생을 안내한다.
5. 서버가 확정한 선공 행동을 기존 전투 효과로 재생한다.
6. 후공 HP가 0이면 경기를 종료하고 후공 행동 이벤트를 만들지 않는다.
7. 후공이 살아 있으면 후공 행동을 재생한다.
8. 양쪽이 생존하면 상태 지속시간과 재사용 대기시간을 갱신하고 다음 라운드를 시작한다.

### 기존 전투 규칙 재사용

PvP용 순수 계산 모듈이 현재 직업·전문화·액티브 스킬의 공격, 치유, 보호막, 치명타,
상태 효과와 재사용 대기시간 규칙을 공유한다. 몬스터 전용 패턴, 몬스터 AI, 도주 확률과
몬스터 보상 로직은 포함하지 않는다. 서버 계산과 브라우저 표시가 같은 규칙 데이터를
사용하도록 하나의 버전 식별자를 둔다.

## 5. 종료, 항복과 재접속

### 정상 종료

- HP가 0이 된 학생에게 1패, 상대에게 1승을 서버가 한 번만 기록한다.
- 경험치, 골드, 빌딩, 아이템, 퀘스트 진행과 월드 HP는 변경하지 않는다.
- 결과 화면에서 양쪽 얼굴, 승자, 사용한 라운드 수와 갱신된 승패만 보여준다.
- 닫으면 전투 전 마을 위치와 원래 월드 상태로 돌아간다.

### 항복

- 일반 몬스터 전투의 `도망` 버튼 위치를 PvP에서 `항복`으로 바꾼다.
- 누르면 취소 가능한 확인창을 한 번 더 표시한다.
- 확정한 학생에게 1패, 상대에게 1승을 기록한다.

### 연결 종료

- 각 클라이언트는 경기 중 짧은 주기로 생존 신호를 보낸다.
- 한 학생의 신호가 끊기면 상대에게 `상대의 재접속을 기다리는 중`과 남은 30초를 표시한다.
- 30초 안에 돌아오면 현재 경기와 라운드를 복원한다.
- 돌아오지 않으면 끊긴 학생의 패배로 처리한다.
- 양쪽 모두 끊기고 장시간 돌아오지 않으면 승패 없이 경기방만 정리한다.
- 수업 서버가 닫히면 새 신청을 막는다. 진행 중 경기는 안전하게 취소하고 승패를 남기지
  않으며 월드 상태를 보존한다.

## 6. PvP 화면

- 왼쪽에 나, 오른쪽에 상대의 캐릭터와 이름·레벨·HP·상태 효과를 표시한다.
- 기존 전투 음악과 공격·피격·보호막·스킬 효과를 재사용한다.
- 문제 풀이 단계, 상대 대기 단계, 주사위 단계와 공격 단계가 명확히 구분되어야 한다.
- 주사위 애니메이션은 전투 장면 중앙에 배치하고 양쪽 색으로 소유자를 구분한다.
- 선공 결과 안내가 끝난 뒤에만 첫 공격 연출을 시작한다.
- 네트워크 응답을 기다리는 동안 버튼을 잠그고 중복 클릭을 막는다.
- PvP에서만 기존 도망 버튼의 문구와 동작을 항복으로 교체한다.

## 7. 왼쪽 클릭 이동

### 입력

- 게임 캔버스의 걸을 수 있는 바닥을 왼쪽 클릭하면 화면 좌표를 월드 좌표로 바꾼다.
- 메뉴, 모달, 버튼, 채팅 입력과 스크롤 영역의 클릭은 이동 입력으로 사용하지 않는다.
- 오른쪽 클릭 캐릭터 프로필과 왼쪽 클릭 이동은 별도 입력으로 처리한다.
- 키보드 이동 입력, 전투 진입, 모달 열기, 맵 전환 또는 새 목적지 클릭은 기존 자동 이동을
  즉시 취소하거나 교체한다.

### 경로

- 기존 월드 충돌 레지스트리가 제공하는 벽, 건물, 우물과 지도 경계를 사용한다.
- 클릭 시점에만 격자 기반 경로 탐색을 실행하고 장애물을 통과하지 않는 경로를 만든다.
- 목적지가 막힌 곳이면 가장 가까운 걸을 수 있는 지점으로 보정한다.
- 지나치게 꺾이는 경로는 충돌 검사를 유지한 채 직선 구간으로 단순화한다.
- 포탈이나 문을 자동으로 작동시키거나 다른 맵까지 연속 이동하지 않는다.
- 바닥에 짧은 파란색 목적지 표시를 보여준다.

## 8. 튜토리얼 초록색 강조

기존 최초 캐릭터 튜토리얼의 안전한 정적 문구에 퀘스트와 같은 초록색 굵은 강조 클래스를
사용한다.

- `명진쌤`
- `W A S D`, `방향키`
- `E`, `N`, `C`
- `문제를 맞히면 공격`
- `5레벨`
- PvP 안내의 `오른쪽 클릭`, `대전 신청`, `20초`, `30면체 주사위`, `항복`

짧은 한 글자 단축키를 일반 HTML 전체에서 자동 검색하지 않는다. 튜토리얼의 통제된 텍스트
조각에 명시적으로 강조를 붙여 다른 단어 내부나 HTML 태그가 잘못 강조되는 일을 막는다.

다른 학생의 프로필을 처음 오른쪽 클릭했을 때 `pvpTutorialSeen` 기록이 없는 캐릭터에게
한 번만 다음 내용을 안내한 뒤, 안내를 닫으면 원래 열려고 했던 프로필을 보여준다.

1. 마을의 다른 학생을 오른쪽 클릭해 프로필 열기
2. 프로필에서 대전 신청하기
3. 같은 문제를 동시에 20초 동안 풀기
4. 매 라운드 30면체 주사위로 공격 순서 정하기
5. PvP에서는 손해가 없고 승패 기록만 남는다는 점

## 9. 안전과 중복 방지

- 모든 변경 요청은 로그인 사용자와 경기 참가자가 일치하는지 확인한다.
- PvP 테이블은 RLS를 강제하고 학생의 직접 INSERT·UPDATE·DELETE 권한을 제거한다.
- 비공개 답안 영역은 참가자도 직접 SELECT할 수 없다.
- 서버 작업은 경기 상태와 라운드 번호를 함께 확인해 오래된 요청을 거절한다.
- 신청, 제출, 판정, 종료에는 중복 호출에도 같은 결과를 내는 요청 키를 사용한다.
- 승패 갱신과 경기 종료는 하나의 트랜잭션으로 처리한다.
- 프로필 응답은 허용된 공개 필드만 새 객체로 구성하고 민감한 저장 데이터는 반환하지 않는다.
- 서버 시각을 제한 시간과 접속 종료 판정의 기준으로 사용한다.

## 10. 오류 안내

- 대상이 마을 밖: `마을에 있는 친구에게만 대전을 신청할 수 있어요.`
- 대상이 다른 활동 중: `지금은 대전을 받을 수 없는 상태예요.`
- 신청 만료: `대전 신청 시간이 지나 취소되었어요.`
- 활성 문제 없음: `선생님이 활성화한 문제집이 없어 대전을 시작할 수 없어요.`
- 먼저 제출한 경우: `답을 제출했어요. 상대가 문제를 푸는 중이에요!`
- 상대 연결 종료: `상대의 재접속을 기다리고 있어요.`
- 서버 오류: 경기를 중단하고 승패와 월드 상태를 변경하지 않은 채 안전한 한국어 안내를 표시한다.

## 11. 검증 기준

### 순수 규칙 검사

- 같은 문제와 동일한 마감 시각 생성
- 정답 정상 효과, 오답과 시간 초과의 50% 효과
- 각 라운드의 독립적인 30면체 주사위와 동률 재굴림
- 선공 처치 시 후공 행동 미생성
- 방어, 치유, 보호막, 상태 효과와 쿨다운
- PvP 결과가 월드 자원과 HP를 변경하지 않음

### 서버 보안 검사

- 당사자 외 신청 수락, 답안 제출, 항복과 경기 조회 거부
- 직접 승패 수정 거부
- 중복 신청·답안·판정·종료의 멱등성
- 승패가 정확히 한 번만 증가
- 비공개 답안과 정답의 조기 노출 방지
- 30초 재접속 성공과 시간 초과 패배
- 양쪽 장기 이탈과 수업 종료의 무승패 정리

### 브라우저 통합 검사

- 두 가짜 로그인 세션의 신청부터 결과까지 전체 흐름
- 먼저 제출한 학생의 대기 안내
- 주사위 애니메이션 후 서버 순서대로 공격
- 프로필 초상화가 현재 얼굴·장비·코스튬을 반영
- PvP의 항복 버튼과 일반 전투의 도망 버튼 분리
- 재접속 시 HP, 라운드와 미처리 이벤트 복원

### 클릭 이동과 튜토리얼 검사

- 클릭 위치 도달과 파란 목적지 표시
- 벽·건물·우물·지도 경계 통과 방지
- 키보드, 모달, 전투와 맵 전환 시 자동 이동 취소
- UI와 채팅 클릭이 이동을 일으키지 않음
- 최초 튜토리얼과 PvP 안내의 승인된 표현만 초록색 굵은 글씨로 강조
