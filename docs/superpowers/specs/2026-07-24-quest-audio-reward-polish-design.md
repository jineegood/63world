# 퀘스트·전투 음악·보상 연출 개선 설계

## 목적

초반 퀘스트가 어린 플레이어에게 더 명확하고 자연스럽게 이어지도록 숫자 강조,
치유 튜토리얼, NPC 전용 대사와 코스튬 선물을 추가한다. 새 전투 MP3를 사용하고
보상 안내가 충분히 읽히도록 표시 시간을 늘린다.

## 1. 퀘스트 숫자 강조

현재 퀘스트 강조 모듈은 지정된 단어만 노란색 또는 초록색으로 표시한다. 여기에
숫자와 단위로 이루어진 목표 표현을 자동으로 찾는 규칙을 추가한다.

- 예: `4마리`, `1회`, `150골드`, `5개`, `3빌딩`
- 숫자와 바로 뒤 단위를 하나의 초록색 굵은 강조로 묶는다.
- 숫자 규칙은 퀘스트 제목, 설명, 진행 대사와 완료 대사에 동일하게 적용한다.
- HTML 특수문자를 먼저 안전하게 처리하는 현재 보안 규칙을 유지한다.
- 이미 단어 강조에 포함된 표현과 겹쳐 중첩된 `<strong>` 태그가 생기지 않게 한다.

## 2. 전투 음악 교체

사용자가 추가한 `assets/1. 전투씬 음악_[cut_83sec].mp3`를
`assets/1. 전투씬 음악.mp3`로 정리한다.

- 오디오 목록의 `battleBgm` 경로를 새 MP3로 변경한다.
- 삭제된 기존 `assets/1. 전투씬 음악.wav`는 복원하지 않는다.
- 일반 전투에서만 새 음악을 사용하고, 보스 맵의 기존 보스 음악 우선 규칙은 유지한다.
- 전투 종료 후 원래 지역 음악으로 돌아가는 기존 동작을 유지한다.

## 3. 보상 표시 시간

공통 보상 단계 생성 함수가 각 단계의 표시 시간과 다음 단계 시작 시점을 함께 계산한다.

- 경험치: 1,500ms
- 골드: 1,500ms
- 퀘스트·고정 보상의 빌딩: 1,500ms
- 몬스터 처치 시 10% 확률로 나온 빌딩: 2,000ms

몬스터 보상 호출부가 `몬스터 우연 획득` 문맥을 명시적으로 전달한다. 퀘스트 보상은
일반 문맥을 사용한다. 경험치 → 골드 → 빌딩 순서, 색상과 효과음은 그대로 유지한다.

## 4. 치유의 우물 튜토리얼

`tut_equip` 다음, `mushroom_hunt` 전에 새 퀘스트를 삽입한다.

- 제목: `다치면 쉬어가기`
- 목표: 치유의 우물 문제를 한 번 맞히기
- 행동 종류: `healWell`
- 설명: `치유의 우물에서 문제를 맞혀 HP를 1회 회복하고 명진쌤에게 보고하기`
- 소규모 보상: EXP 3, 골드 20, 빌딩 0

처음 수락할 때 명진쌤이 안전한 훈련 공격을 예고한 뒤 다음 연출을 한 번만 실행한다.

1. 적 공격 효과음을 재생한다.
2. 플레이어 피격 흔들림을 재생한다.
3. 플레이어 HP를 죽지 않는 값인 1로 만든다.
4. `회복 훈련이란다. 치유의 우물에서 문제를 풀어 보렴.`이라는 안내를 보여준다.

우물 문제를 맞히면 현재 HP와 관계없이 `healWell` 진행도를 올린다. 레벨업이나 다른
회복으로 HP가 먼저 가득 차도 퀘스트가 막히지 않는다. 틀린 답에는 진행도를 주지 않는다.

기존 저장에서 이미 `mushroom_hunt` 이후 단계에 진입한 플레이어는 새 튜토리얼 때문에
퀘스트 순서가 되돌아가지 않도록 새 퀘스트를 자동 완료 처리한다.

## 5. 코스튬 퀘스트와 전용 아이템

`tut_costume`의 수락 시 150골드 지급을 제거한다. 설명과 대사도 구매가 아니라 상남의
선물을 받는 내용으로 변경한다.

새 코스튬:

- ID: `cs_questSproutRibbon`
- 이름: `새싹 리본`
- 슬롯: 코스튬 악세서리
- 능력치: 없음
- 외형: 기존 리본 외형을 재사용하되 초록색 계열로 표시
- `questOnly: true`로 지정해 일반 코스튬 상점 목록에는 표시하지 않는다.

`tut_costume`이 수락된 상태에서 상남과 처음 대화하면 일반 상점보다 전용 대화를 먼저
보여준다.

> 아! 명진쌤의 부탁을 받고 왔구나. 이 아이템을 이번만 특별히 공짜로 주마!

`선물 받기` 버튼을 누르면 다음을 원자적으로 처리한다.

1. 아직 없을 때만 `새싹 리본`을 코스튬 보관함에 추가한다.
2. 코스튬 퀘스트 진행도를 1로 만들고 완료 보고 가능 상태로 바꾼다.
3. 저장과 HUD 갱신을 수행한다.
4. 아이템 획득 안내를 보여준다.

대화나 버튼을 반복해도 아이템은 한 개만 지급한다. 기존 `buyCostume` 행동으로 일반
코스튬을 구매해도 이 퀘스트는 완료되지 않는다.

## 6. 상점 NPC 첫 대화

해당 튜토리얼 퀘스트가 수락됐고 아직 목표를 달성하지 않았을 때, 관련 NPC와 처음
상호작용하면 짧은 전용 대화를 먼저 보여준다. 대화 후 버튼으로 기존 상점 화면을 연다.

- `tut_shop`: 장비 상점의 무기·방어구 상인
  - `명진쌤이 첫 장보기를 부탁했구나? 천천히 보고 네게 필요한 장비를 골라 보렴.`
- `tut_costume`: 옷 상인 상남
  - 코스튬 선물 대화와 지급 흐름 사용
- `tut_accessory`: 특별 상인 새나리
  - `명진쌤의 심부름으로 왔구나? 악세서리는 가지고만 있어도 힘을 보태 준단다.`
- `tut_enhance`: 대장장이 진명
  - `명진쌤이 강화 연습을 보내셨군. 실패해도 배운 것이 남으니 겁먹지 말게.`

펫 수정구는 사람이 아니므로 전용 첫 대화를 추가하지 않는다. 일반 방문이나 이미
전용 대화를 본 뒤의 방문은 기존 상점 화면을 바로 연다. 퀘스트 상태에 `npcIntroSeen`
표시를 저장해 재접속 후에도 같은 첫 대사가 반복되지 않게 한다.

## 7. 퀘스트 내용 일관성 점검

전체 16개 기존 퀘스트와 새 우물 퀘스트를 검토한다.

- `slime_hunt` 목표를 설명과 대사에 맞춰 3마리로 통일한다.
- `slime_hunt` 완료 대사에서 슬라임 보스를 잡았다는 표현을 제거한다.
- `swamp_king_hunt` 완료 대사에서 아직 싸우지 않은 명진쌤 보스에게 졌다는 표현을
  제거하고 엘리트 좀비 처치와 다음 문이 열린 내용으로 교체한다.
- 일반 몬스터 퀘스트 완료 대사에는 보스를 처치했다는 표현이 없어야 한다.
- `target` 숫자와 설명·지시 대사의 목표 숫자가 서로 일치해야 한다.
- 엘리트 전투 대사는 `eliteOnly` 퀘스트에서만 사용한다.

## 8. 코드 구조

데이터는 기존 역할별 파일에 둔다.

- `src/quest-data.js`: 새 퀘스트, 순서, 수정된 대사와 목표
- `src/quest-text.js`: 숫자·단위 강조
- `src/costume-data.js`: 퀘스트 전용 코스튬 정의
- `src/gameplay-polish-v2.js`: 보상 단계 시간과 문맥 계산
- `src/audio-manifest.js`: 새 전투 MP3 경로

새 행동은 `src/quest-tutorial-polish-v3.js`에 모은다. `game.js`에는 기존 우물·상점·퀘스트
진입점에서 이 모듈을 늦게 호출하는 최소 연결만 추가한다. 기존 거대 파일에 새 정책을
직접 쌓지 않는다.

## 9. 검증

- 숫자 강조가 안전하고 모든 지정 단위를 초록색으로 표시하는 단위 테스트
- 새 퀘스트 순서, 보상, 목표와 기존 저장 마이그레이션 테스트
- 훈련 공격이 한 번만 HP를 1로 만들고 우물 정답만 진행도를 주는 테스트
- 전용 코스튬이 상점에서 제외되고 한 번만 지급되는 테스트
- 네 NPC의 첫 대화가 퀘스트 상태에서 한 번만 나타나는 테스트
- 보상 단계가 1,500ms이며 몬스터 우연 빌딩만 2,000ms인 테스트
- MP3 경로와 파일 존재, WAV 참조 제거 테스트
- 모든 퀘스트 목표 숫자와 일반/엘리트 표현 일관성 검사
- 전체 `npm.cmd test` 실행
