# 자동 검사와 클라우드 저장 분리 설계

## 목적

자동 검사 중에는 실제 Supabase 클라우드 저장에 연결하지 않는다. 실제 게임을 브라우저에서 실행할 때의 클라우드 저장 설정과 동작은 변경하지 않는다.

## 현재 문제

`src/cloud-config.js`에 실제 연결 설정이 들어 있다. 공용 브라우저 검사 도구가 이 설정을 그대로 읽지만, 검사 환경에는 브라우저의 네트워크 기능인 `fetch`가 없다. 또한 신규 캐릭터 생성 2.2초 뒤 튜토리얼이 열리는데, 전투 프레임 검사가 이를 닫지 않고 전투를 시작해 일시정지 상태에 막힌다.

## 선택한 방식

- 공용 브라우저 검사에서는 클라우드 설정을 기본적으로 빈 값으로 바꿔 로컬 저장 방식으로 실행한다.
- 신규 캐릭터로 전투를 시작하는 자동 검사는 튜토리얼을 정상 종료한 다음 전투를 시작한다.
- 클라우드 자체를 검사하는 전용 테스트는 필요할 때 명시적으로 가짜 서버 응답을 제공할 수 있게 한다.
- 실제 `src/cloud-config.js`의 주소와 공개 키는 수정하지 않는다.
- 학생 저장 데이터와 게임 기능은 수정하지 않는다.

## 확인 기준

1. 재현된 `combat-frame-pipeline` 검사가 통과한다.
2. 절대 경로를 사용한 브라우저 부팅 검사가 통과한다.
3. `npm test` 전체가 실패 없이 끝난다.
4. 일반 브라우저 실행에서는 기존 클라우드 설정이 그대로 유지된다.

## 작업 범위 밖

- Supabase 보안 정책 변경
- 학생 비밀번호 저장 방식 변경
- Git 저장소 복구
- 게임 밸런스와 화면 기능 변경
