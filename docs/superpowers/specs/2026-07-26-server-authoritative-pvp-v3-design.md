# 63월드 서버 판정 PvP v3 설계

## 목적

이미 구현된 학생 친선 PvP의 화면과 진행 방식을 유지하면서, 학생 브라우저가 전투 능력치·정답 판정·주사위·피해량·승패를 조작할 수 없도록 한다. PvP는 경험치, 골드, 빌딩, 아이템, 월드 HP에 영향을 주지 않고 캐릭터 기록에는 승리와 패배만 남긴다.

이번 작업은 로컬 코드와 검사까지만 진행한다. GitHub 업로드, Vercel 배포, Supabase migration 적용과 Edge Function 배포는 하지 않는다. 모든 서버 보안 단계와 실제 서버 검사가 끝날 때까지 `serverAuthorityV3Enabled`는 `false`로 유지한다.

## 유지할 게임 방식

- 마을에 있는 서로 다른 학생끼리만 대전을 신청하고 수락할 수 있다.
- 상대 캐릭터를 오른쪽 클릭하면 현재 장비와 코스튬이 반영된 얼굴, 이름, 레벨, 직업, 전문화, 승패를 보여준다.
- 대전 시작 때 서버가 양쪽의 PvP 임시 HP를 최대치로 채운다.
- 매 라운드 두 학생에게 같은 문제를 20초 동안 보여준다.
- 먼저 제출한 학생도 상대가 제출하거나 시간이 끝날 때까지 기다린다.
- 두 제출이 모인 뒤 서버가 양쪽의 30면체 주사위를 굴린다. 동점이면 다시 굴린다.
- 높은 숫자의 학생이 먼저 공격한다. 첫 공격으로 상대 HP가 0이 되면 후공은 취소된다.
- 오답과 시간 초과 행동은 원래 효과의 50%만 적용한다.
- 항복하면 항복한 학생에게 1패, 상대 학생에게 1승을 기록한다.
- 한쪽 연결이 끊기면 30초 동안 재접속을 기다리고, 돌아오지 않으면 남아 있는 학생의 승리로 처리한다. 양쪽이 모두 사라지면 승패 없이 취소한다.

## 선택한 구현 방식

현재 `pvp-match-v1` Edge Function, PvP 테이블, Realtime 구독, 브라우저 화면을 유지하고 서버 저장 통로만 v3에 연결한다.

이 방식은 PvP를 통째로 다시 만드는 것보다 변경 범위와 오류 가능성이 작다. 또한 현재와 같은 요청 수를 유지하므로 Supabase 무료 사용량을 불필요하게 늘리지 않는다.

검토한 대안은 다음과 같다.

1. **기존 PvP에 v3 권한 연결 — 선택**
   - 기존 화면, 동시 제출, 주사위 애니메이션, 재접속 기능을 재사용한다.
   - 전투 시작 능력치와 승패 저장만 v3 서버 자료를 사용하게 바꾼다.
2. 별도의 `pvp-match-v3`를 새로 제작
   - 기존 코드와 분리하기 쉽지만 같은 기능을 다시 만들고 배포 대상도 늘어나므로 지금은 이점보다 비용이 크다.
3. 브라우저 계산을 유지하고 마지막 승패만 서버에서 검사
   - 공격력과 정답 결과를 조작할 수 있어 보안 목표를 충족하지 못한다.

## 서버가 소유할 정보

### 전투 참가자 능력치

대전 수락 시 서버는 `player_core_v3`, `player_inventory_v3`, `player_skills_v3`, `player_preferences_v3`와 서버 카탈로그를 읽어 양쪽 스냅샷을 만든다.

- 레벨, 직업, 전문화
- 최대 HP
- 장착 장비와 강화 단계
- 공격력과 방어력
- 습득한 액티브 스킬과 랭크
- 공개 가능한 외형과 코스튬

브라우저가 presence 요청에 담은 레벨, 장비, 스킬, 공격력, 방어력, HP는 전투 계산에 사용하지 않는다.

### 문제와 정답

서버가 활성 문제집에서 문제 하나를 고른다. 브라우저에는 문제 ID, 문장, 선택지만 보내고 정답은 비공개 테이블에 보관한다. 학생이 보낸 답은 서버가 채점하고, 브라우저가 보낸 `correct`, 피해량 또는 정답 키는 받지 않는다.

### 주사위와 전투 결과

양쪽 입력이 모이면 Edge Function이 암호학적 난수로 각 학생의 1~30 주사위를 만든다. 서버가 확정한 순서로 기존 PvP 규칙 모듈이 피해, 보호막, 회복, 상태 효과, 쿨다운을 계산한다.

브라우저에는 애니메이션에 필요한 공개 이벤트만 순서대로 보낸다. 비공개 정답, 원본 제출 답안, 다른 학생의 숨겨진 저장 자료는 보내지 않는다.

## 승패 기록

기존 PvP 경기 종료 함수가 경기 행을 잠근 뒤 다음 작업을 한 번의 서버 작업으로 처리한다.

- 경기가 아직 끝나지 않았는지 확인
- 승자와 패자가 실제 참가자인지 확인
- `player_core_v3.pvp_wins`와 `player_core_v3.pvp_losses`를 각각 1 증가
- 기존 공개 프로필 호환을 위해 `pvp_records_v1`도 같은 결과로 갱신
- 경기 종료 시각, 사유, 승자, 패자를 기록
- 두 학생의 PvP busy 상태 해제

같은 종료 요청이 반복되면 처음 한 번만 기록한다. 브라우저는 승수나 패수를 직접 보내거나 수정할 수 없다.

## 요청과 동시 실행 안전

- 모든 요청은 Supabase JWT로 로그인한 학생 ID를 확인한다.
- 신청 대상 외에는 브라우저가 다른 학생 ID를 행동 주체로 지정할 수 없다.
- 제출은 경기 ID, 라운드 번호, 행동 ID, 답, 요청 ID만 받는다.
- 선택한 행동은 서버 스냅샷의 직업, 전문화, 습득 스킬, 쿨다운과 일치할 때만 사용한다. 그렇지 않으면 기본 공격으로 바꾼다.
- 학생 한 명당 한 라운드의 첫 제출만 인정한다.
- 두 기기가 동시에 마지막 답을 제출해도 한 서버 작업만 해당 라운드를 확정하도록 경기 행을 잠그는 서버 함수로 처리한다.
- 공개 경기 상태와 이벤트 테이블은 참가자만 읽을 수 있고 학생은 직접 추가·수정·삭제할 수 없다.
- 비공개 정답과 원본 제출 답안은 학생이 직접 읽을 수 없다.

## 브라우저 연결

기존 `src/pvp-client.js`, `src/pvp-ui.js`, `src/pvp-battle.js`를 유지한다.

- 보안 전환 스위치가 꺼져 있을 때는 현재 배포 버전과 같은 흐름을 유지한다.
- 스위치가 켜진 최종 배포에서는 PvP 프로필과 전투가 v3 서버 스냅샷과 v3 승패 기록을 사용한다.
- Realtime 위치 공유와 채팅은 변경하지 않는다.
- PvP 요청 횟수는 신청·수락, 라운드당 각 학생의 제출 한 번, 기존 heartbeat와 Realtime 알림 수준을 유지한다.

## 오류와 복구

- v3 캐릭터가 없으면 대전을 시작하지 않고 캐릭터 준비가 필요하다고 안내한다.
- 양쪽이 마을에 없거나 다른 전투 중이면 신청 또는 수락을 거절한다.
- 문제가 없으면 승패 없이 신청 또는 경기를 취소한다.
- 오래된 라운드 제출은 거절하고 최신 경기 상태를 다시 내려준다.
- Edge Function 또는 네트워크 오류 때 브라우저 계산으로 대신 진행하지 않는다. 서버 상태를 다시 불러온다.
- 재접속하면 서버의 HP, 보호막, 쿨다운, 상태 효과, 문제 남은 시간을 복원한다.

## 검사 기준

### 서버 규칙

- v3 장비와 스킬만으로 전투 스냅샷이 만들어진다.
- 브라우저가 조작한 공격력, 방어력, HP, 장비, 스킬, 승패가 무시된다.
- 같은 문제와 같은 마감 시간이 양쪽에 제공되고 정답은 노출되지 않는다.
- 먼저 제출해도 공격 순서에 영향을 주지 않는다.
- 30면체 동점 재굴림과 높은 숫자의 선공이 서버에서 결정된다.
- 오답과 시간 초과는 50% 효과다.
- 선공 처치 시 후공이 취소된다.

### 저장과 권한

- 학생은 PvP와 v3 핵심 테이블을 직접 수정할 수 없다.
- 정상 처치, 항복, 접속 종료의 승패가 v3에 정확히 한 번 기록된다.
- 중복 종료 요청과 동시 제출이 중복 승패 또는 중복 라운드를 만들지 않는다.
- PvP는 월드 HP, 경험치, 골드, 빌딩, 아이템, 퀘스트를 바꾸지 않는다.
- 참가자가 아닌 학생은 경기 상태와 이벤트를 읽을 수 없다.
- 비공개 정답과 원본 답안은 학생 권한으로 읽을 수 없다.

### 기존 기능 회귀

- 오른쪽 클릭 프로필, 얼굴 확대, 신청·수락·거절이 유지된다.
- 같은 문제 동시 풀이, 대기 안내, 주사위 애니메이션, 전투 효과가 유지된다.
- 항복 확인창과 재접속 복원이 유지된다.
- 이동, Realtime 위치 공유, 채팅에 변화가 없다.
- 전체 자동 검사가 통과하고 `serverAuthorityV3Enabled`가 `false`인지 확인한다.

## 제외 범위

- PvP 보상, 랭킹, 시즌, 연승 보너스
- 관전, 재생, 토너먼트
- 자동 매칭과 마을 밖 신청
- PvP 전용 능력치 보정
- 이번 작업 중 GitHub, Vercel, Supabase 실제 배포
