### 3단계 · 보안 로그인 v2 (7월 23일)
그전까지 학생 정보는 **각자 브라우저 안에만** 저장됐고 비밀번호도 그대로 노출됐습니다.
이것을 Supabase(인터넷 데이터베이스)로 옮기고,
- 학생 로그인 / 교사 로그인 분리
- 교사만 학생 목록·비밀번호 초기화·계정 삭제 가능
- 학생은 남의 저장값을 못 읽게 차단
- 문제집·수업 설정을 반 전체가 공유

까지 만들었습니다.

### 4단계 · 게임플레이 다듬기 (7월 23~24일)
초반 난이도 완화, 오답 시 처벌 완화, 사냥터 치유의 우물 추가,

전투 배경음악, 퀘스트 문구 정리 등을 했습니다.

개발 중 쌓인 임시 파일들을 정리하고 `.gitignore`(기록에서 제외할 폴더 목록)를 만들었습니다.

### 6단계 · 클릭 이동 + PvP 1차 (7월 25일)
마우스로 클릭하면 벽을 피해 알아서 걸어가는 이동을 넣고,
학생끼리 대결하는 PvP의 첫 버전(대결 신청, 실시간 대결)을 만들었습니다.

### 7단계 · 서버 권한 v3 — **가장 큰 작업** (7월 26일)
이번 프로젝트에서 제일 규모가 큰 작업입니다. 한 문장으로 말하면:

> **"게임의 모든 판정을 학생 컴퓨터가 아니라 서버가 하도록 통째로 옮긴 것"**

왜 필요했냐면, 그전까지는 학생이 브라우저 개발자도구를 열어
골드·경험치·강화 성공 여부를 마음대로 바꿀 수 있었고,
**문제집의 정답이 학생 브라우저로 통째로 내려가고 있었습니다.**

그래서 5단계에 걸쳐 옮겼습니다.

| 단계 | 내용 |
|---|---|
| 1단계 | 캐릭터 생성·불러오기·맵 이동을 서버가 처리 |
| 2단계 | 상점 구매, 장비/코스튬 장착, 무기 강화, 전문화, 스킬 습득, 펫 소환을 서버가 계산 |
| 3단계 | 일반 전투 — 문제 출제·채점, 명중·치명타·피해량·보상까지 서버가 계산 |
| 3단계 확장 | 엘리트 몬스터 3종 + 최종 보스 전용 규칙·보상 |
| 4단계 | 퀘스트 17개의 수락·진행·완료·보상 |
| 5단계 | PvP가 서버 능력치만 쓰고 승패도 서버가 기록 |

이제 **정답은 학생 브라우저로 내려가지 않습니다.** 문제만 내려가고, 채점은 서버가 합니다.

### 8단계 · 실제 서비스 적용 (7월 26일 밤)

## 2. 게임 기능 전체 설명

### 접속과 캐릭터
- 학생은 **캐릭터 이름 + 비밀번호**로 로그인합니다. 없는 이름이면 새로 생성됩니다.
- 직업 3종: **전사**(대검/방어), **마법사**(지팡이/냉기·화염), **사제**(책/신성·암흑)
- 외형(머리·얼굴 등)을 랜덤 또는 직접 고를 수 있습니다.
- Lv.5가 되면 **전문화**(각 직업의 두 갈래 중 하나)를 선택합니다.

### 세계와 이동
지도는 총 9곳입니다.

| 장소 | 설명 |
|---|---|
| 63마을 | 시작 마을. 상점·명예의 전당·NPC(명진쌤)·사냥터 포탈 |
| Lv.1 고요한 숲 | 첫 사냥터 |
| Lv.4 황량한 사막 | 두 번째 사냥터 |
| Lv.7 으스스한 늪지 | 세 번째 사냥터 |
| 보스 방 | 각 사냥터 포탈로 입장 |
| 장비상점 내부 | 무기 상인 의석 / 방어구 상인 상미 |
| 빌딩 화폐 상점 내부 | 특별 상인 새나리 / 옷 상인 상남 |
| 대장간 내부 | 무기 강화 |
| 펫 상점 내부 | 펫 소환 |

이동은 **키보드(WASD/방향키)** 와 **마우스 클릭** 둘 다 됩니다.
클릭하면 벽·건물을 피해서 자동으로 길을 찾아 걸어갑니다.

### 전투 = 문제 풀이
63월드의 핵심입니다.
1. 몬스터에게 다가가면 전투 시작
2. 선생님이 등록한 문제집에서 **그 사냥터에 맞는 문제**가 나옴
3. 맞히면 내 공격이 나가고, 틀리면 몬스터가 공격
4. 명중/빗나감, 치명타, 보호막, 중독·암흑(지속 피해), 기절 등이 적용됨
5. 이기면 경험치·골드·빌딩화폐, 지면 경험치 일부 손실

**이 모든 계산은 서버가 합니다.** 학생 화면은 결과를 보여주기만 합니다.

### 성장
- 레벨업 → 스킬 포인트 획득 → 스킬창(N키)에서 스킬 습득
- 스킬 트리는 전문화별로 갈라집니다
- 장비/스텟 창(C키)에서 착용 장비와 능력치 확인

### 경제
- **골드**: 일반 장비 구매
- **빌딩 화폐**: 특별 아이템·코스튬 구매
- **무기 강화**: 대장간에서 비용을 내고 시도, 성공/실패가 있음 (성공 확률도 서버 계산)
- **펫**: 펫 상점에서 소환(뽑기). 뽑은 펫이 따라다님
- **코스튬**: 외형을 바꾸는 옷. 퀘스트 보상으로도 받음

### 퀘스트
총 **17개**. 마을 NPC와 대화하며 진행합니다.
그중 일부는 **행동형 튜토리얼**입니다 — "스킬을 배워보세요", "우물에서 회복해보세요" 처럼
실제로 해봐야 완료됩니다. 처음 하는 학생이 헤매지 않도록 화면에 강조 표시가 뜹니다.

### 보스
- 각 사냥터에 **엘리트 몬스터**가 있고, 보스 포탈로 **보스 방** 입장
- 늪지 보스를 잡으면 **최종 보스 포탈**이 열립니다
- 보스는 전용 패턴과 전용 보상이 있습니다

### PvP (학생 대결)
- 다른 학생에게 대결 신청 → 실시간 대결
- 능력치는 **서버에 저장된 진짜 장비·스킬**로만 계산 (브라우저 조작 무시)
- 승패는 서버가 기록. 중간에 나가거나 접속이 끊겨도 결과가 한 번만 기록됩니다

### 함께 즐기는 요소
- **채팅**: 같은 맵 학생들과 대화
- **실시간 위치 공유**: 다른 학생 캐릭터가 움직이는 게 보임
- **명예의 전당**: 마을 건물에서 랭킹 확인
- **춤추기(Z키)** 같은 소소한 동작

### 선생님 기능 (교사 대시보드)
| 탭 | 기능 |
|---|---|
| 👨‍🎓 학생 관리 | 학생 목록·현황, 비밀번호 초기화, 계정 삭제, 캐릭터 초기화 |
| 📚 문제집 관리 | 문제집 생성/삭제, 문제 직접 추가, 여러 문제 한 번에 붙여넣기, 문제집 켜기/끄기, 사냥터 지정, AI 문제집 생성 |
| ⚙️ 수업 설정 | 교사 비밀번호 변경, **서버 열기/닫기**, 치트 도구 켜기/끄기 |

"서버 닫기"를 하면 학생이 접속하거나 계속 플레이할 수 없습니다. 수업 외 시간에 닫아두면 됩니다.
변경은 학생 화면에 약 15초 안에 반영됩니다.

### 치트 도구 (테스트용)
경험치·골드·빌딩화폐 지급, 즉시 처치, 즉시 강화, 이동속도 5배 등.
**기본은 꺼져 있고** 교사 설정에서 켜야 보입니다. 시연·테스트용입니다.

## 4. GitHub · Vercel · Supabase — 무엇이 어디서 도나

세 곳이 각각 다른 일을 합니다.

```
[선생님/학생 브라우저]
        │
        ├── 게임 화면·파일 ────────► Vercel (웹사이트 배포)
        │
        └── 로그인·저장·전투판정 ──► Supabase (데이터베이스 + 서버)

[개발 기록·백업] ──────────────► GitHub
```

### GitHub — 코드 보관소
- 주소: `github.com/jineegood/63world`
- 지금까지 107번의 저장 기록이 있고, 언제든 과거 시점으로 되돌릴 수 있습니다.
- **현재 상태: 로컬과 GitHub이 완전히 같습니다.** 안 올라간 변경 없음. ✅
- 다만 현재 작업 가지(브랜치) 이름이 `local-latest-20260723`이고,
  `main`이라는 오래된 가지가 따로 남아 있습니다. 헷갈릴 수 있어 정리하면 좋습니다.

### Vercel — 게임 배포
- 프로젝트 이름 `63world`
- GitHub에 올리면 자동으로 웹사이트가 새로 배포됩니다.
- 학생은 이 주소로 접속해서 게임을 합니다.

### Supabase — 데이터베이스 + 서버 (무료 계정)
학생 계정, 캐릭터 정보, 문제집, PvP 기록이 여기 저장됩니다.
서버에서 도는 프로그램 5개도 여기 있습니다.

| 서버 프로그램 | 하는 일 |
|---|---|
| `student-combat-v3` | 전투 문제 출제·채점·보상 |
| `pvp-match-v1` | PvP 대결 진행 |
| `teacher-reset-password` | 학생 비밀번호 초기화 |
| `teacher-delete-student` | 학생 계정 삭제 |
| `teacher-reset-player-v3` | 학생 캐릭터 초기화 |

### 보안 구조 (핵심)
쉽게 말해 **"학생 브라우저는 아무것도 믿지 않는다"** 가 원칙입니다.

- 학생은 **문제집의 정답을 절대 받지 못합니다.** 문제만 받고, 답은 서버에 보내서 채점받습니다.
- 학생은 다른 학생의 데이터를 읽거나 고칠 수 없습니다.
- 골드·경험치·강화 결과를 브라우저에서 조작해서 보내도 **서버가 거부합니다.**
- 같은 요청을 여러 번 보내도 보상은 한 번만 들어갑니다.
- 두 기기에서 동시에 접속해도 최신 서버 값으로 맞춰집니다.

### 무료 한도 관리 (선생님이 걱정하신 부분)
Supabase 무료 계정이므로 서버 호출량을 아끼도록 설계돼 있습니다.

- **캐릭터 이동과 채팅은 데이터베이스를 거치지 않습니다.** 가볍게 실시간 전송만 합니다.
  → 학생들이 계속 움직여도 사용량이 늘지 않습니다.
- 전투는 **시작할 때 1번 + 답을 제출할 때마다 1번**만 서버를 부릅니다.
- 문제집·수업 설정은 15초마다 한 번만 확인합니다.

다만 **실제 28명이 동시에 쓸 때 사용량이 어느 정도인지는 아직 측정 전**입니다.
(아래 5번 참고)

### 켜고 끄는 스위치
`src/cloud-config.js` 파일 안에 두 개의 스위치가 있습니다.

```js
securityV2Enabled: true,        // 보안 로그인 사용
serverAuthorityV3Enabled: true, // 서버가 모든 판정
```

지금은 둘 다 **켜짐(true)** 상태입니다.
⚠️ 문제가 생겨도 `false`로 되돌리는 것만으로는 복구되지 않습니다.
데이터베이스 권한도 함께 되돌려야 합니다 (자세한 건 `docs/server-authority-v3-cutover-checklist.md`).

## 6. 다음 목표 — AI 문제집

### 지금 상태: **"AI 문제집"은 아직 진짜 AI가 아닙니다**
교사 대시보드에 `AI 문제집 생성` 버튼이 이미 있지만,
실제로는 `game.js` 안에 **미리 적어둔 단어 목록과 계산식**으로 문제를 찍어내는 방식입니다.

- "영어/영단어/단어"가 요청에 들어가면 → 미리 저장된 영단어 25개 중에서 출제
- "소수 나눗셈"이 들어가면 → 정해진 숫자 조합으로 계산 문제 생성
- 그 외 → 기본 패턴

즉 **선생님이 무엇을 요청하든 결과가 거의 정해져 있습니다.**
"5학년 2학기 분수의 덧셈" 같은 걸 요청해도 원하는 문제가 나오지 않습니다.

### 앞서 정한 방향 (이어감)
- AI가 문제를 만들면 **선생님이 검토한 뒤 등록**
- 모든 문제는 **4지선다형**
- 한 번에 **최대 20문제**

### 만들려면 필요한 것
진짜 AI를 쓰려면 **AI 회사의 API 키**가 필요하고, 이 키는
학생 브라우저에 절대 넣으면 안 됩니다(누구나 볼 수 있고, 요금이 청구됩니다).
그래서 **Supabase 서버 프로그램 안에 숨겨두고** 교사만 부를 수 있게 해야 합니다.
기존 교사용 서버 프로그램들과 똑같은 방식이라 구조는 이미 준비돼 있습니다.

```
선생님이 "5학년 분수 덧셈 20문제" 입력
        ↓
Supabase 서버 프로그램 (교사인지 확인 → API 키는 여기 숨겨져 있음)
        ↓
AI가 4지선다 20문제 생성
        ↓
선생님 화면에 목록으로 표시 → 검토·수정·삭제
        ↓
"등록" 누르면 문제집으로 저장 → 학생 전투에 출제
```

### 다음에 정해야 할 것
1. **어느 AI를 쓸지** (Claude / GPT 등) — API 키 발급이 필요합니다
2. **문제 출제 장소를 어떻게 고를지** — 문제집을 만들 때 어느 사냥터에서 나올지 지정하는 방식
3. **검토 화면 형태** — 표로 볼지, 한 문제씩 볼지, 마음에 안 드는 문제만 다시 만들지
