## 심각도 상

### 1. 스킬창 버튼 이중 실행 — 죽은 정의가 아직 살아있음 ✅ 조치 완료 (2026-07-17)
- 수정: game.js:5592의 `addEventListener('click', openSkillTreeModal)` → `onclick = () => openSkillTreeModal()` (늦은 바인딩, 이후 패치가 onclick을 덮어써 핸들러 일원화)
- 검증: jsdom 클릭 재현으로 openModal 호출 수정 전 2회 → 수정 후 1회 확인, 클릭 경로가 V35 스킬창(v35 마커 114개)을 여는 것 확인, node --check + 테스트 26종 + 스모크 6종 통과
- 근거: game.js:5592 / 6163 / 7865 / 11338 / 11435
- 5592에서 버튼을 clone 후 `addEventListener('click', openSkillTreeModal)`로 **그 시점의 함수 값**(원본 4189 정의)을 직접 바인딩. 이후 패치(6163, 7865, 11435)는 clone 없이 `.onclick`만 덮어씀 → 5592 리스너가 그대로 생존.
- 11338에서 `openSkillTreeModal = function openSkillTreeModalV35()`로 재할당되므로, 클릭 1회에 **원본(구버전) 스킬창 + V35 스킬창이 둘 다 실행**된다. 마지막 렌더가 이겨서 눈에 잘 안 띄지만 이중 실행이며, 구버전 로직의 부작용이 함께 돈다.
- 조치: 5592의 직접 참조를 `() => openSkillTreeModal()`로 바꾸거나, V35 시점에 버튼을 다시 clone해서 리스너를 일원화.

### 2. 치트 패널이 모든 학생에게 상시 노출

- 🧪 치트 토글이 아무 인증 없이 항상 표시. +EXP/+Gold/몬스터 즉시처치/퀘스트 즉시완료/무기 즉시강화를 학생이 자유롭게 사용 가능 → 성장 보상 체계 무력화.
- 조치: cheatCluster를 기본 `hidden`으로 두고 교사 인증(`__teacherAuthed`) 시에만 표시.

### 3. 서버 게이트·권한이 전부 클라이언트 판정
- 근거: src/admin-dashboard.js:412-416(localStorage만 읽음), 428-439(30초 폴링), game.js:5224
- 콘솔에서 `localStorage.setItem(...)` 또는 `window.__teacherAuthed=true` 한 줄로 우회 가능. 교사 기본 비밀번호(6363)와 학생 비밀번호 전원이 평문 저장이며, 교사 대시보드는 학생 비번을 평문 표시(admin-dashboard.js:38).
- 서버 없는 구조상 완전한 강제는 불가능. 조치: 비번 컬럼 마스킹, 우회 난이도 상향, 나머지는 학급 규칙으로 운영.

## 심각도 중

### 4. localStorage 쿼터 초과 시 저장 예외가 전투 루프로 전파
- 근거: src/player-store.js:50 (`storage.setItem` try/catch 없음), savePlayer는 전투 중 빈번 호출(game.js:7573 등)
- 공용 PC에 계정·문제집·오답로그가 쌓여 쿼터를 넘기면 setItem이 throw → 전투 시퀀스 중간에 미포착 예외로 상태 꼬임.
- 조치: write를 try/catch로 감싸 실패 시 false 반환 + 토스트 안내.

### 5. 도망 판정 raw 타이머가 재진입 가드 밖
- 근거: game.js:5833(setTimeout 1050ms → monsterCounterAttack), 5844, 6709 경유로 실행됨
- closeModal은 combatSequenceController만 무효화하고 이 타이머는 안 지움. 도망 판정 중 모달이 닫히면 전투 밖에서 반격이 실행됨. monsterCounterAttackV25(7252)는 `game.player` null 가드도 없어 로그아웃 직후면 TypeError 가능.
- 조치: 타이머를 컨트롤러 schedule로 편입하거나 발화 시 `modalState.type==='combat'` + `game.player` 재확인.

### 6. 멀티탭 동시 플레이 시 진행 손실
- 근거: storage 이벤트 리스너 부재, savePlayer가 플레이어 통째로 덮어씀(game.js:326)
- 같은 계정 두 탭이면 마지막 저장이 다른 탭 진행(골드/경험치)을 조용히 덮어씀. 교실 환경에서 발생 가능.
- 조치: storage 이벤트로 타 탭 감지 후 경고, 또는 updatedAt 비교.

### 7. ui-tooltip.js 재실행 가드 부재
- 근거: src/ui-tooltip.js:64-65, 90, 92 — `__ysTooltipReady`를 세팅만 하고 시작부에서 검사 안 함. setInterval(120ms) 해제 로직 없음.
- 스크립트 재평가 시 인터벌·capture 리스너가 중첩. zone-banner.js, combat-keys.js(register 중복 시 input-router.js:12가 throw), admin-dashboard.js도 같은 패턴.
- 조치: 각 모듈 IIFE 상단에 `if (window.__X__) return;` 가드 통일.
