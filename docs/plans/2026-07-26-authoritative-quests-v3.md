# 서버 권한 퀘스트 v3 구현 계획

목표는 학생 브라우저가 퀘스트 진행도나 보상을 직접 늘리지 못하게 하고, 이미 서버가 확인한 실제 행동만 퀘스트에 반영하는 것이다.

## 1. 서버 퀘스트 목록과 순서

- `src/quest-data.js`에서 퀘스트 ID, 순서, 목표, 수락 지급품, 완료 보상을 생성한다.
- 서버는 직전 퀘스트 보상을 받은 경우에만 다음 퀘스트 수락을 허용한다.
- 서버 상태 `active`, `ready`, `claimed`는 화면에서 쓰는 `accepted`, `ready`, `completed`로 변환한다.

## 2. 실제 행동으로만 진행

- 장비 구매·장착, 스킬 습득, 강화 시도, 펫 소환은 각 서버 함수가 성공한 뒤 진행한다.
- 일반·엘리트 몬스터 처치는 서버 전투 승리 처리 안에서 진행한다.
- 코스튬 선물은 해당 퀘스트가 진행 중일 때만 전용 서버 함수가 한 번 지급한다.
- 치유의 우물은 서버가 문제를 출제·채점하고, 정답일 때 HP 회복과 퀘스트 진행을 함께 처리한다.

## 3. 수락과 보상

- 수락 시 지급되는 흰 망토와 빌딩 화폐도 서버가 지급한다.
- 완료 보상 경험치·골드·빌딩·아이템은 서버가 한 번만 지급한다.
- 모든 변경은 캐릭터 revision과 request ID로 중복·두 기기 충돌을 막는다.

## 4. 브라우저 연결

- 서버 보안 스위치가 켜진 경우 수락, 보상, 코스튬 선물, 우물 회복은 서버 응답을 받은 뒤에만 화면에 반영한다.
- 구매·장착·스킬·강화·펫·전투 뒤에는 응답에 포함된 최신 퀘스트 상태를 사용한다.
- 스위치가 꺼진 현재 게임은 기존 흐름을 그대로 사용한다.

## 5. 검사

- 순서 건너뛰기, 목표 미달 보상, 중복 수락·보상, 가짜 행동 종류, 다른 학생 지정 요청을 거부한다.
- 같은 요청 반복과 두 기기 revision 충돌에서 보상이 중복되지 않는지 검사한다.
- 치유 문제 정답과 다음 문제 정답이 학생 브라우저에 미리 전달되지 않는지 검사한다.
- 17개 퀘스트의 수락 지급품, 목표, 보상이 원본 데이터와 일치하는지 검사한다.
