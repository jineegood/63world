# 비개발자용 수정 요청 가이드

이 문서는 개발자가 아닌 사용자가 Codex나 ChatGPT에게 안전하게 수정 요청을 하기 위한 안내서입니다.

## 가장 중요한 원칙

한 번에 많이 고치려고 하지 말고, 작은 문제 하나씩 고치는 것이 안전합니다.

특히 이 프로젝트는 예전에 여러 번 패치가 덧붙으면서 `game.js`가 커졌습니다. 그래서 새 기능을 바로 추가하기보다, 먼저 관련 파일을 확인하고 테스트를 돌리는 방식이 좋습니다.

## 파일을 쉽게 이해하기

- `index.html`: 화면에 보이는 버튼, 입력창, 모달의 뼈대입니다.
- `style.css`: 색, 크기, 위치, 여백 같은 디자인입니다.
- `game.js`: 실제 게임이 움직이는 핵심 파일입니다. 제일 조심해야 합니다.
- `src/core-utils.js`: 여러 곳에서 같이 쓰는 작은 도구 함수입니다.
- `src/game-data.js`: 직업, 경험치, 기본 아이템, 기본 몬스터 같은 기본 데이터입니다.
- `src/quest-data.js`: 퀘스트 목록입니다.
- `src/patch-data.js`: 펫, 강화, 던전, 후반 패치 데이터입니다.
- `tests/`: 수정 후 깨진 곳이 없는지 확인하는 검사 파일입니다.

## 수정 요청 전에 준비하면 좋은 것

버그라면 아래 내용을 적어 주세요.

```text
어떤 화면에서:
무엇을 눌렀는지:
기대한 결과:
실제로 나온 결과:
콘솔 오류가 있으면:
```

예시:

```text
어떤 화면에서: 전투 화면
무엇을 눌렀는지: 스킬 버튼
기대한 결과: 몬스터 HP가 줄어야 함
실제로 나온 결과: 아무 반응이 없음
콘솔 오류가 있으면: submitCombatAnswer is not defined
```

## Codex에게 이렇게 요청하면 좋습니다

```text
기존 동작은 유지하면서 이 문제만 고쳐줘.
먼저 관련 파일을 찾아보고, 왜 문제가 생겼는지 설명해줘.
수정은 작게 하고, 마지막에 전체 테스트를 돌려줘.
```

데이터를 바꾸고 싶을 때:

```text
아이템/몬스터/스킬 데이터만 수정하고 싶어.
가능하면 game.js를 직접 고치지 말고 src의 데이터 파일에서 고쳐줘.
수정 후 데이터 테스트를 돌려줘.
```

화면 디자인을 바꾸고 싶을 때:

```text
화면 배치나 디자인만 수정하고 싶어.
게임 로직은 건드리지 말고 index.html과 style.css 중심으로 확인해줘.
수정 후 브라우저에서 깨지는 부분이 없는지도 봐줘.
```

## 조심해야 하는 요청

아래 요청은 위험할 수 있습니다.

- `game.js` 맨 아래에 새 패치를 붙여줘
- 일단 전체를 한 번에 고쳐줘
- 테스트는 안 돌려도 돼
- 전투, 보상, 저장 방식을 한 번에 다 바꿔줘
- 온라인 서버까지 한 번에 붙여줘

이 프로젝트는 이미 여러 패치가 누적된 상태라, 큰 수정은 버그를 다시 만들 가능성이 높습니다.

## 수정 후 꼭 확인할 것

전체 검사:

```powershell
powershell -NoProfile -ExecutionPolicy Bypass -File tools/run-baseline.ps1 all
```

또는:

```powershell
node --run test
```

데이터를 많이 바꿨다면:

```powershell
node --run extract:data
node --run test
```

## 새 기획을 시작할 때 좋은 순서

1. 지금 플레이하면서 불편한 점과 버그를 적습니다.
2. 버그와 새 기능을 분리합니다.
3. 버그를 먼저 고칩니다.
4. 브라우저 테스트를 추가합니다.
5. 30명 동시 접속을 위한 서버 기획을 따로 세웁니다.
6. 그다음 새 기능을 개발합니다.

## 30명 동시 접속에 대한 쉬운 설명

지금 게임은 “내 컴퓨터 브라우저 안에 저장되는 게임”에 가깝습니다.

30명이 동시에 쓰려면 “모두가 접속하는 공용 서버”가 필요합니다. 서버가 학생 정보, 캐릭터, 아이템, 전투 결과, 문제 풀이 기록을 저장해야 합니다.

그래서 온라인 버전은 새 기능 하나가 아니라 새 단계의 기획으로 보는 것이 안전합니다.
