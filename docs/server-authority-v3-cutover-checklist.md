# 63월드 서버 보안 전환 체크리스트

이 문서는 새 서버 저장 기반을 실제 수업용 게임에 켜기 전에 반드시 끝내야 할 작업을 정리한다. 현재 `serverAuthorityV3Enabled`는 `false`이며, 아래 항목이 모두 끝날 때까지 그대로 둔다.

## 현재 완료된 기반

- 학생 성장 정보, 인벤토리, 스킬, 퀘스트, 환경설정을 분리한 v3 테이블
- 학생이 성장 테이블을 직접 수정하지 못하는 권한 정책
- 서버 캐릭터 생성 및 불러오기
- 외형·음량·튜토리얼 확인값만 저장하는 환경설정 요청
- 서버가 허용 장소와 레벨을 확인하는 맵 이동 요청
- 중복 요청 방지용 요청 번호와 변경 충돌 감지
- 교사 전용 테스트 캐릭터 초기화 및 보안 기록 조회 기능
- 기존 게임에 영향을 주지 않는 비활성 전환 스위치

## 실제 전환 전 필수 작업

- [ ] 2단계: 골드·빌딩 상점 구매, 장비 장착, 강화, 스킬 습득을 서버 계산으로 변경
- [ ] 3단계: 일반 전투 세션, 문제 출제·채점, 피해량, 몬스터 처치 보상을 서버 계산으로 변경
- [ ] 4단계: 퀘스트 수락·진행·완료와 보상을 서버 계산으로 변경
- [ ] 5단계: PvP가 v3 능력치만 사용하고 승패를 서버에서 기록하도록 변경
- [ ] 현재 220ms Supabase 위치 방송을 WebRTC 이동 공유와 저빈도 예비 통로로 교체
- [ ] 기존 테스트 계정의 v3 캐릭터를 관리자 화면에서 명시적으로 초기화
- [ ] 기존 `player_profiles_v2.data` 값을 v3 성장 정보로 복사하지 않는지 확인
- [ ] 28명 동시 접속 모의검사에서 로그인, 이동, 전투, 채팅, PvP를 확인
- [ ] Supabase 무료 한도 경고 기준을 확인: DB 250MB, Realtime 50만 메시지, Edge 10만 호출, Egress 3GB, 동시 연결 40
- [ ] 전체 자동검사와 실제 브라우저 확인을 모두 통과
- [ ] 사용자에게 운영 Supabase migration/Edge Function 적용 승인을 받음
- [ ] 사용자에게 GitHub 업로드 및 Vercel 배포 승인을 받음
- [ ] 마지막으로 `serverAuthorityV3Enabled`를 `true`로 바꾸고 새 테스트 계정으로 다시 확인

## 전환 순서

1. 운영 수업이 없는 시간에 Supabase migration과 Edge Function을 적용한다.
2. 테스트 계정의 v3 캐릭터를 초기화한다.
3. GitHub와 Vercel에 완성본을 배포한다.
4. 전환 스위치를 켠 상태로 교사 1명과 학생 테스트 계정 2개를 검사한다.
5. 캐릭터 생성, 재로그인, 상점, 전투, 퀘스트, PvP, 다른 기기 동시 접속을 확인한다.
6. 이상이 없을 때만 학생 계정 사용을 시작한다.

## 되돌리기

학생 수업이 시작되기 전에 문제가 발견되면 전환 스위치를 다시 `false`로 끄고 배포한다. v3 성장값을 학생이 수정할 수 있는 v2 JSON으로 복사하지 않는다. 학생이 v3에서 실제 플레이를 시작한 뒤에는 v2로 되돌리면 진행 기록이 갈라질 수 있으므로, 그때는 임의로 되돌리지 말고 v3 문제를 수정한 뒤 재배포한다.

## 운영 중 확인

- 보안 기록에서 반복되는 잘못된 맵 이동, 설정 필드 위조, 변경 충돌을 확인한다.
- 요청 영수증은 7일, 보안 기록은 30일이 지난 항목을 교사 정리 기능으로 삭제한다.
- 좌표와 채팅은 성장 보상의 근거로 사용하지 않는다.
- 서비스 역할 키는 Supabase 서버 환경에만 두며 브라우저 파일이나 GitHub에 넣지 않는다.
