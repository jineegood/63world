# 63월드 서버 보안 전환 체크리스트

이 문서는 새 서버 보안 방식을 실제 수업용 게임에 켜기 전에 확인할 항목을 정리한다.
현재 `serverAuthorityV3Enabled`는 `false`이며, 아래 승인과 실서버 검사가 끝날 때까지 그대로 유지한다.

## 현재 코드로 준비된 것

- [x] 학생 성장 정보, 인벤토리, 장비, 스킬, 퀘스트, 환경설정을 분리해 저장하는 v3 기반
- [x] 학생이 다른 학생의 저장값을 직접 읽거나 수정하지 못하게 하는 권한 정책
- [x] 서버에서 캐릭터 생성·불러오기와 허용된 맵 이동만 처리하는 1단계 기능
- [x] 골드·빌딩 상점 구매 가격과 보유 화폐를 서버가 직접 확인
- [x] 일반 장비와 코스튬의 소유권·장착·해제를 서버가 직접 확인
- [x] 무기 강화 비용, 성공 확률, 등급 변화를 서버가 직접 계산
- [x] 전문화 선택 조건과 스킬 포인트·선행 스킬 조건을 서버가 직접 확인
- [x] 펫 소환 비용·랜덤 결과·소유권·동행 펫을 서버가 직접 확인
- [x] 같은 요청의 중복 실행과 다른 행동으로의 재사용 방지
- [x] 두 기기의 저장 순서가 엇갈리면 최신 서버 값으로 되돌리는 충돌 처리
- [x] 기존 게임에는 영향을 주지 않는 비활성 전환 스위치

## 아직 남은 개발 단계

- [ ] 3단계: 일반 전투 행동, 문제 출제·채점, 피해량, 몬스터 처치 보상을 서버 계산으로 변경
- [ ] 4단계: 퀘스트 수락·진행·완료와 보상을 서버 계산으로 변경
- [ ] 5단계: PvP가 v3 능력치만 사용하고 승패를 서버에서 기록하도록 변경
- [ ] 기존 테스트 계정의 v3 캐릭터를 관리자 화면에서 명시적으로 초기화
- [ ] 기존 `player_profiles_v2.data`를 v3 성장 정보로 자동 복사하지 않는지 재확인

이동 좌표와 채팅·교실 내 실시간 위치 공유는 지금처럼 가볍게 유지한다. 따라서 서버 보안 계산을
늘려도 학생들이 서로 움직이는 모습은 계속 볼 수 있고, 이동할 때마다 무거운 DB 요청을 보내지 않는다.

## 실제 서버 적용 전 필수 검사

- [ ] 운영 수업이 없는 시간에 Supabase migration을 순서대로 적용
- [ ] 실 Supabase에서 migration 전체가 오류 없이 실행되는지 확인
- [ ] 테스트 학생 2명과 교사 1명으로 가입·로그인·캐릭터 생성 확인
- [ ] 두 기기에서 동시에 구매해도 돈이나 아이템이 중복되지 않는지 확인
- [ ] 장비·코스튬 장착, 강화 성공·실패, 전문화, 스킬 습득을 확인
- [ ] 잘못된 가격·잔액·강화 결과·다른 사용자 ID를 보낸 공격 요청이 거부되는지 확인
- [ ] 28명 동시 접속 모의검사에서 로그인, 이동, 전투, 채팅, PvP를 확인
- [ ] Supabase 무료 한도 사용량과 경고 설정 확인
- [ ] 전체 자동검사와 실제 브라우저 확인을 모두 통과
- [ ] 사용자에게 Supabase migration 적용 승인을 받음
- [ ] 사용자에게 GitHub 업로드와 Vercel 배포 승인을 받음

## 전환 순서

1. 수업이 없는 시간에 승인된 Supabase migration을 적용한다.
2. 관리자 화면에서 테스트 계정의 v3 캐릭터를 초기화한다.
3. 현재 완성본을 GitHub와 Vercel에 배포한다.
4. 교사 1명과 테스트 학생 2명으로 전환 스위치를 켠 시험 버전을 확인한다.
5. 로그인, 상점, 장비, 강화, 스킬, 전투, 퀘스트, PvP, 동시 접속을 차례로 점검한다.
6. 이상이 없을 때만 학생 계정 사용을 시작한다.

## 문제가 생겼을 때

학생 수업을 시작하기 전에 문제가 발견되면 전환 스위치를 다시 `false`로 두고 배포한다.
v3 진행값을 예전 v2 JSON 저장값으로 자동 복사하지 않는다. 이미 학생이 v3에서 플레이한 뒤라면
임의로 되돌리지 말고 문제를 수정한 다음 다시 검증한다.
