Excel은 네 시트를 모두 렌더링해 글자와 표 배치를 확인했고 수식 오류가 없다. Excel 저장만으로 게임 코드가 자동 변경되지는 않는다.

### 공격력 해석 — 매우 중요

- 과거 시트의 `강화 후 공격력` 값이 실제 평상시 공격력이었다.
- 그 숫자를 새 시트의 `기본 공격력`으로 옮겼고, 과거의 낮은 기본 공격력 열은 삭제했다.
- 새 기본 공격력에는 제작자가 요청했던 몬스터 피해 60% 상향분이 이미 반영되어 있다.
- 게임에 옮길 때 공통 1.6배를 다시 곱하면 피해가 중복 상승하므로 절대 다시 곱하지 않는다.
- 패턴에 적힌 `본인 강화 3턴`은 위 60% 상향과 별개의 몬스터 기술 상태다. 구현할 때 현재 기본 공격력에 별도 기술 강화 효과를 적용한다.

## 4. 확정 출현 규칙

기본 원리:

- 한 구간의 첫 번째 레벨 몬스터 두 마리는 모두 한 번씩 출현한다.
- 다음 레벨 조우는 해당 레벨의 두 마리 중 한 마리를 무작위로 뽑는다.
- Lv.12 이상은 한 마리씩만 있으므로 확정 출현한다.

구간별 구성:

- 1~10층: Lv.5 두 마리 모두 + Lv.6 중 랜덤 1마리 + Lv.7 중 랜덤 1마리
- 11~20층: Lv.6 두 마리 모두 + Lv.7 중 랜덤 1마리 + Lv.8 중 랜덤 1마리
- 21~30층: Lv.7 두 마리 모두 + Lv.8 중 랜덤 1마리 + Lv.9 중 랜덤 1마리
- 31~40층: Lv.8 두 마리 모두 + Lv.9 중 랜덤 1마리 + Lv.10 중 랜덤 1마리
- 41~50층: Lv.9 두 마리 모두 + Lv.10 중 랜덤 1마리 + Lv.11 중 랜덤 1마리
- 51~60층: Lv.10 두 마리 모두 + Lv.11 중 랜덤 1마리 + Lv.12 확정
- 61~63층: Lv.12 → Lv.13 → Lv.14 모두 확정, 총 세 번 조우

예시: 1~10층의 레벨 흐름은 `5, 5, 6, 7`이다. Lv.5 두 마리는 모두 나오고, Lv.6 조우에서는 빌딩 스톰프/고장 난 전화기 중 한 마리, Lv.7 조우에서는 오염된 슬라임/폭주 복사기 중 한 마리가 나온다.

## 5. 다음 Opus가 구현할 순서

1. 최종 Excel의 17마리만 `src/raid-rules.js`에 반영한다.
2. Excel의 기본 공격력 값을 그대로 사용하고, 기존 던전 공통 피해 배율 `1.6`은 제거하거나 `1.0`으로 바꿔 중복 적용을 막는다.
3. 현재 하나만 열린 1~10층 외에 11~20, 21~30, 31~40, 41~50, 51~60, 61~63 선택지를 단계적으로 연다.
4. 방을 시작할 때 해당 방의 실제 몬스터 조우 목록을 한 번만 뽑아 Supabase 방 상태에 저장한다.
5. 각 브라우저가 따로 랜덤을 돌리면 세 학생에게 다른 몬스터가 보이므로 절대 그렇게 만들지 않는다.
6. 새로고침·일시 접속 끊김·재접속 후에도 처음 뽑힌 동일한 조우 목록을 복구한다.
7. 첫 두 마리는 같은 레벨의 A/B가 모두 나오게 하되, 순서는 고정해도 되고 한 번 섞어도 된다. 같은 몬스터가 두 번 나오는 것만 막는다.
8. Excel의 패턴을 구조화된 행동으로 구현한다. 단일/전체 다단 공격, 기절, 독, 냉기, 보호막, 회복, 흡혈, 반격, 공격 빗나감, 강화, 다음 기술 예약 및 2배 효과가 포함된다.
9. 기존 몬스터 그림과 에셋을 먼저 찾아 연결한다. 없는 에셋이 있을 때만 제작자에게 해당 이름을 짧게 알려 달라고 요청한다.
10. 크롬 세 개로 같은 몬스터·같은 체력·같은 이벤트 순서가 보이는지 확인한다.

현재 Excel 규칙은 아직 게임 코드에 적용되지 않았다. 이번 작업은 제작자 요청대로 Excel과 인수인계 정리까지만 했다.

- Supabase는 방, 참가자, 학생별 서로 다른 문제, 정답 판정, 실시간 상태 동기화를 맡는다.
